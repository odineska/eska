# Ревью ESKA и Explorer от 18 ноября 2026

Исходные ревизии ветки `codex/form-editor` — `5e31b21e` в ESKA
и `4a11697` в Explorer. В обзор вошли точки входа и связи всех 13 пакетов
Rust workspace, клиент расширения, webview и инструменты упаковки.
Подробно проверены операции, где ошибка могла затронуть пользовательские
файлы, сохранённую работу в Git или состояние открытого редактора.
По графу обычных зависимостей `eska-project-core` самостоятелен внутри
workspace, а общий CLI делегирует запуск через `eska-tool-runtime`
и использует `eska-presentation` для представления команд и ошибок.

## Результаты

| Сценарий | Найденная проблема и исправление |
| --- | --- |
| Завершение задачи | После `shelve` рабочее дерево чистое, и `finish` мог удалить ветку, к которой привязана полка. Проверка полки и переход на базовую ветку теперь проходят под общей блокировкой. Политика с сохранением ветки по-прежнему позволяет завершить задачу. |
| Импорт и распаковка | Изменение BSL в подготовленной выгрузке могло пройти проверку имени, типа и UUID. Оба пути публикации теперь сверяют содержимое со снимком всей выгрузки. При обходе для подсчёта файлов больше не требуется хранить список всех путей. |
| Формы Designer XML | Разное текстовое представление одного числового ID могло оставить ссылку копии на исходный элемент или позволить удалить используемый элемент. Копирование и поиск ссылок при удалении используют общий числовой разбор. |
| IDE-сессии | При поздней отмене сервер мог скрыть уже выданный ID формы, снимка или проекции либо итог изменения конструктора запроса. Сервер возвращает подтверждение операции, которая изменила состояние. |
| Соединение Explorer | После переподключения ID сессии мог повториться. Отложенный запрос привязан к исходному процессу. Если обработчик остановки выдаёт ошибку, Explorer выполняет остальные обработчики и завершает процесс. |
| Навигация в форме | При обновлении XML старый индекс мог указывать на другой обработчик. Webview передаёт ревизию и ID сессии, а Extension Host проверяет их до перехода. |
| Внешний анализатор | Унаследованный потомком канал мог удерживать `eska-check` после завершения прямого процесса. Дедлайн и отмена теперь охватывают ожидание обоих потоков. Уже заблокированное системное чтение может продолжаться в фоне до появления данных или закрытия канала потомком. |
| Форматтер | Форматирование встроенного запроса повторно разбирало тот же XML или BSL. Подготовка правок теперь использует уже выбранный запрос, итоговый текст по-прежнему проверяется. Форматтер также проверяет фактический путь в выбранном проекте и записывает файл с ошибкой чтения или подготовки в отчёт. |

В экспериментальном Rust API у `FinishError` появился вариант `Shelf`.
Изменения CLI описаны в руководствах по [VCS](../user-guide.md),
[сборке](../build-tool.md), [анализу](../check-cli.md) и
[форматированию](../formatting.md).

## Проверки

- На Linux aarch64 с Rust 1.99.1 прошли `cargo fmt --check`, `cargo check`,
  `cargo clippy --all-targets --all-features -- -D warnings` и `cargo test`.
  В стандартном прогоне 1842 теста прошли, 59 отмечены `ignored`.
  Во всех проверках CLI использовался соседний `eska-playground`.
- На 1С 8.3.27.2342 прошли `unpack` и `import` реального EPF в отдельном
  проекте. Сверены имя, UUID, исходный файл и манифест. Дополнительно прошёл
  штатный тест редактирования формы с загрузкой в 1С и обратной выгрузкой XML.
- Для `eska finish` в ru/en проверены отказ при наличии полки и восстановление
  разных версий файла в Git index и рабочем дереве через `unshelve`.
- На XML-схеме размером 97 650 байт с 800 наборами данных измерена команда
  `eska-fmt Schema.xml --query-index 799 --check --format json`. Медиана семи
  чередующихся запусков после прогрева снизилась со 131 до 100 мс в debug-сборке.
  Отчёты исходного и нового бинарников совпали побайтно, как и вывод
  общего входа `eska fmt` в ru/en.
- Прошли 53 Python-теста упаковки, установки и служебных сценариев, а также
  14 тестов каталога и покрытия форм.
- Совпадают наборы ключей ru/en в пяти парах ресурсов Fluent (3471 ключ)
  и в `package.nls` Explorer (112 ключей).
- В Explorer прошли проверка TypeScript, сборка и 951 из 959 Node-тестов
  со свежими `eska-project` и `eska-fmt`. Из восьми пропущенных тестов
  пять требуют Windows, ещё три проверяют совместимый `bsl-analyzer-app`.
  При явной проверке локального анализатора 0.2.67 эти три сценария вернули
  `incompatible`. Его контракт не объявляет `lsp --mode stdio`.
- В VS Code 1.109.0 под X11 переход к обработчику формы после правки
  несохранённого XML прошёл в ru/en. Сценарий смены подключения подтвердил
  корректное завершение старого процесса и открытие нового.
