# HTTP-отладка 1С

VS Code обменивается с `eska-debug` сообщениями DAP по stdin/stdout. Rust-адаптер
соединяется с `dbgs` по HTTP. Клиент 1С подключается к своей информационной базе
через настроенный runner. Адрес базы и `debug.url` задаются независимо.

Для файловой базы профиль может запускать собственный сервер через
`debug.managed = true`. Он слушает `127.0.0.1` и выбирает свободный порт.
`debug.port` задаёт фиксированный порт, например для подключения отдельно
запущенного клиента. Адрес показывается в Debug Console. Адаптер завершает
свой сервер при отключении и EOF. Для внешнего сервера задайте `debug.url`.

## Критерии приёмки

ESKA использует [DAP](https://github.com/microsoft/debug-adapter-protocol/blob/main/debugAdapterProtocol.json)
для интерфейса IDE и проверенный на платформе HTTP-обмен для управления
предметами 1С. Возможности OnecDebugAdapter учитываются при определении
минимального функционального набора. Пользовательская семантика и пределы
операций определяются контрактом ESKA и проверяются в установленном VSIX.

- Из проекта можно запустить или подключить отладку в профиле `test` либо
  `prod`, настроить автоподключение, выбрать существующий предмет и перейти
  из стека к исходнику основной конфигурации или подключённого расширения.
- Evaluate работает в выбранном кадре. Вложенные значения раскрываются
  лениво, выражение выполняется один раз, большие коллекции доступны порциями
  со стабильными индексами и явными ошибками чтения.
- Точки, условия, счётчики, логпоинты и остановка по ошибке доступны через
  интерфейс VS Code. При отмене, разрыве и повторном подключении проверяются
  сроки завершения запросов, действительность ссылок и сохранность чужих
  процессов. Для `prod` действует проверка исходников, профили остаются
  в локальном защищённом файле.
- Для приёмки на 1С 8.3.27.2342 и из установленного VSIX фиксируются сценарии,
  время DAP и HTTP отдельно, CPU в простое, RSS при раскрытии и повторном
  подключении, размеры VSIX (до 5 МиБ), установленных файлов (до 10 МиБ)
  и JS (до 3,5 МиБ). Проверяются ru и en.

## Контракт с dbgs

Проверенная версия платформы — 8.3.27.2342. Запросы идут методом POST
на `/e1crdbg/rdbg?cmd=…`. XML передаётся в UTF-8. Корневой `request` без
пространства имён, его поля — в `debugRDBGRequestResponse`. Ответ
`response` находится в `debugBaseData`; вложенные поля принадлежат
пространствам операции, идентификаторов, точек или вычислений. Сервер может
добавить UTF-8 BOM и прислать пустое тело для подтверждения или пустого опроса.

На 1С 8.3.27.2342 отдельно проверены модули собственной внешней обработки
EPF. При загрузке объекта через `ВнешниеОбработки.Создать` в серверном
контексте стек содержит `ExtMDModule` с URL `sfile:///…`, UUID объекта и
свойством модуля объекта. При запуске через `/Execute` в кадре управляемой
формы приходит `file:///…`, UUID дескриптора формы и свойство модуля формы.
В обоих случаях сервер принял точку до загрузки EPF, а затем остановился
на заданной строке. В проверенных URL пробелы и кириллица переданы как текст.
Значение поля `version` менялось между запусками одного файла по одному
и тому же пути. Контрольную сумму артефакта нужно проверять отдельно.
При самостоятельном запуске адаптер сопоставляет кадры клиентской копии
с исходниками, подтверждёнными манифестом сборки. [Запуск готовой EPF](eska-debug-standalone.md#запуск-готовой-epf)

### EPF в проекте Explorer

Выберите проект ESKA типа `processing`. В локальных настройках профиля
`test` или `prod` укажите собранный файл EPF. Explorer сохраняет его
в `.eska/settings_local.toml`.

```toml
[test.debug.external_processing]
artifact = "artifacts/МояОбработка.epf"
```

Путь относителен к корню проекта. Абсолютный путь тоже допустим. Рядом с
артефактом нужен манифест сборки. Адаптер сверяет артефакт и снимок исходников
выбранного проекта, затем запускает приватную копию EPF через `/Execute`.
При необходимости подтвердите открытие в штатном диалоге 1С.

Для подключения к уже загруженной обработке добавьте в эту таблицу
`debug_url` с полным URL развёрнутой EPF и её SHA-256 в имени родительского
каталога. Подключаются существующие предметы выбранных типов
`auto_attach_types`. При запуске 1С открывает приватную копию по её собственному
пути. Для профиля `prod` Explorer сохраняет проверку Git и выбор пользователя
перед началом отладки. [Правила развёртывания EPF для подключения](eska-debug-standalone.md#подключение-к-загруженной-epf)

В установленном Explorer проверены серверное подключение, шаги из общего
модуля в EPF и обратно, а также переподключение к другой сборке в том же
клиенте 1С. Для новой сборки обновите путь артефакта и `debug_url` в профиле
и заново подключите отладчик.

### Запросы HTTP

| Действие DAP | Обмен с dbgs | Подтверждённое поведение |
| --- | --- | --- |
| initialize | локальный обмен | Адаптер объявляет конфигурирование, Evaluate и отмену ожидающего результата |
| launch / attach | `attachDebugUI`, `setAutoAttachSettings` | `registered` открывает сессию. Файловый alias — `DefAlias`. Профиль задаёт типы автоподключения. Новый клиент запускается после `configurationDone` |
| setBreakpoints | `setBreakpoints`, `bpWorkspace` | Пересылается весь набор обычных и условных точек, точек со счётчиком и логпоинтов. Пустой список снимает точки модуля |
| setExceptionBreakpoints | `setBreakOnRTE` | Фильтр `all` включает остановку на ошибках. Поле `condition` ограничивает остановки по вхождению текста в сообщение об ошибке |
| exceptionInfo | — | Текст исключения из текущей остановки выбранного потока, без дополнительного запроса к 1С |
| Выбор предмета | `getDbgTargets`, `clearBreakOnNextStatement`, `attachDetachDbgTargets` | Новый предмет поступает также через `targetStarted`. Существующий можно выбрать по ID из списка |
| threads / stackTrace | `pingDebugUIParams&dbgui=…` | `callStackFormed` содержит кадры от вызывающего к текущему. DAP разворачивает порядок |
| scopes / variables | `evalLocalVariables` или `evalExpr` | Локальные переменные относятся к выбранному `stackLevel`. Составные значения раскрываются отдельным запросом |
| evaluate | `evalExpr` | Вычисление выполняется один раз в выбранном кадре. `expressionResultID` связывает запрос с синхронным ответом или событием `exprEvaluated`. `expressionID` связывает последующие раскрытия с результатом |
| setVariable | `modifyValue` | Новое выражение вычисляется в выбранном кадре и присваивается локальной переменной, свойству или индексированному элементу. Платформа решает, допускает ли значение присваивание |
| continue, next, stepIn, stepOut | `step` с `Continue`, `Step`, `StepIn`, `StepOut` | Ответ перечисляет возобновлённые предметы. Адаптер обновляет состояние каждого из них. Следующая остановка приходит отдельным событием |
| pause | `setBreakOnNextStatement` | Штатный сервер просит работающие предметы текущей регистрации остановиться на ближайшем операторе BSL. Каждый фактически остановленный предмет сообщает свой стек |
| disconnect | продолжение остановленных предметов, `detachDebugUI` | Завершает регистрацию и освобождает остановленные предметы. Адаптер управляет процессом клиента, только если сам его запустил |

У идентификатора UI время жизни одной регистрации, у идентификатора предмета —
одного сеанса 1С, у DAP `frameId` и `variablesReference` — одной остановки
этого предмета. После продолжения старые ссылки недействительны. `pres` и
`exceptionStr` передаются в Base64 с текстом UTF-8. Ошибки транспорта
локализованы. Результаты пользовательских выражений возвращаются в DAP.

На вычисление и получение результата отводится до четырёх секунд суммарно.
Пока адаптер ждёт `dbgs`, редактор может читать уже полученный стек и
отменять запросы `evaluate`, `variables` и `setVariable`. При отмене адаптер закрывает
соединение этого запроса и игнорирует поздний результат. Если 1С уже начала
выполнять выражение, отмена ожидания не останавливает и не откатывает его
побочные эффекты.

При длительной потере связи адаптер сообщает о разрыве и завершает сеанс.
Если при повторном подключении `dbgs` ещё считает базу занятой, адаптер
сообщает об этом отдельно. Подключение можно повторить после освобождения
регистрации. Адаптер отключает только собственный идентификатор регистрации.

Повторные запросы одного значения в одном кадре переиспользуют ссылку.
Для индексированных коллекций `indexedVariables` сообщает размер, а DAP
`variables` принимает `filter`, `start` и `count`. Адаптер передаёт диапазон
в `dbgs` как `startIndex` и `pageSize`, сохраняет абсолютные индексы и
возвращает пустой список за последним элементом. Лимиты — 512 дочерних
значений в ответе, 8192 ссылок и 32 уровня вложенности. Превышение лимита
возвращает ошибку на языке интерфейса.

Перечисляемые значения, например `Соответствие` и `ФиксированноеСоответствие`,
также раскрываются диапазонами. В имени пары виден ключ, а внутри пары
доступны `Ключ`, `Значение` и дочерние свойства значения. При ошибке чтения
свойства адаптер показывает сообщение платформы или локализованное пояснение,
если платформа прислала пустое сообщение. Остальные свойства сохраняются.

Команда **Set Value** в дереве переменных принимает выражение BSL. Например,
для присваивания строки введите `"текст"`. После замены составного значения
адаптер выдаёт новую ссылку для раскрытия. Старые ссылки на это значение и
его дочерние элементы недействительны. Сохранённые результаты Evaluate и
элементы перечисления доступны для чтения. Если присваивание уже отправлено
в 1С, отмена ожидания не откатывает изменение.

Точки и стек сопоставляются с Designer XML через UUID владельца из общей
модели проекта, идентификатор свойства модуля платформы и имя расширения из
Designer XML. В workspace используется конфигурация и расширения того приложения
из `workspace.members`, в которое входит выбранный проект. Если проект входит
в несколько приложений, выберите одно из них в `analysis.default_application`.
Несколько расширений с одним именем Designer дают ошибку при запуске.
Состав приложения не нужно повторять в `launch.json`.
Модули EPF сопоставляются по полному URL загруженного артефакта и UUID
дескриптора. [Отладка EPF из проекта](#epf-в-проекте-explorer)

Explorer использует `eska/listDebugTargets` с ответом
`{ "targets": [{ "id": "...", "kind": "...", "session": "...", "user": "..." }] }`
и `eska/attachDebugTarget` с параметром `{ "id": "..." }`. Запрос
`eska/getAutoAttachTypes` возвращает `available` и `selected`. Запрос
`eska/setAutoAttachTypes` с полем `types` изменяет автоподключение новых
предметов текущей сессии. Предметы, уже подключённые к отладчику, остаются
доступны. Для основной
ветки `prod` адаптер вызывает установленный `eska-vcs` по внутреннему
контракту компонентов. В workspace проверяется рабочая копия, содержащая
конфигурацию и расширения приложения. Если их корни относятся к разным Git
репозиториям, результат проверки — `unverified`, и продолжение требует явного
выбора использовать текущие исходники. Запущенный отладчик обращается к `dbgs` сам.

См. [спецификацию DAP](https://microsoft.github.io/debug-adapter-protocol/specification).

## Воспроизведение

В собственный уникальный каталог соседнего `eska-playground` скопируйте
`tests/fixtures/forms/native-dendrogram/source` как `src`. Добавьте
`src/Ext/ManagedApplicationModule.bsl`.

```bsl
Процедура ПриНачалеРаботыСистемы()
    A = 41;
    B = Увеличить(A);
    Сообщить(B);
КонецПроцедуры

Функция Увеличить(Число)
    Результат = Число + 1;
    Возврат Результат;
КонецФункции
```

Подготовьте манифест проекта типа `configuration` и файловую базу командами
`ibcmd infobase create --data=base`, `ibcmd infobase config import --data=base src`
и `ibcmd infobase config apply --data=base`. Укажите `base/db-data`, свой
runner и локальный HTTP endpoint в профиле `test`. Запустите `dbgs` на этом
порту. Для графического клиента требуется рабочий дисплей. При Xvfb задайте
`DISPLAY` и `GDK_BACKEND=x11`, чтобы клиент не выбрал пользовательский Wayland.
На ALT Linux 10 стенда клиенту также нужна совместимая с этой системой
`libatomic`; это зависимость платформы 1С, а не адаптера. Перед созданием базы
создайте каталог данных; через Distrobox передавайте абсолютные пути.

```sh
export ESKA_TEST_ROOT="$(realpath ../eska-playground)"
export ESKA_DEBUG_LIVE_PROJECT="<абсолютный путь к своему проекту>"
cargo test -p eska-debug direct_http_breakpoint_and_selected_frame -- --ignored
ESKA_DEBUG_ROUNDS=8 ESKA_DEBUG_TIMINGS=1 cargo test --release -p eska-debug \
  --test native_dap native_dap_release_series -- --ignored --nocapture
```

Для серии с одним профилем `prod` назовите профиль `prod` в собственном демо и
задайте `ESKA_NATIVE_PROFILE=prod`. Тест использует явное решение
`--sources current`. В тесте Explorer `test/debug-http-host.cjs` стенд
передаёт `ESKA_HOST_HTTP_FIXTURE` с путями `binary`, `settings` и `source`.
Для проверки attach до запуска теста запустите отдельный клиент с
`/DEBUG -http -attach /DEBUGGERURL <URL dbgs>`.

Для проверки управляемого сервера задайте `managed = true` в `[test.debug]`
вместо `url` и запустите `native_managed_debug_server_lifecycle` из
`--test native_dap`. Сценарий проверяет запуск клиента, остановку, закрытие
слушателя при `disconnect` и EOF и сохранность слушателя, занимающего заданный
порт. Последняя проверка задаёт занятый порт в настройках временного проекта.

`ESKA_DEBUG_TIMINGS` выводит имена HTTP-операций и миллисекунды в stderr.
DAP-время включает обработку адаптера, HTTP и ожидание асинхронного результата.
`stackTrace` отдаётся из события остановки и не требует отдельного запроса.

## Приёмка и замеры

Стенд — Linux ARM64, 1С 8.3.27.2342 в ALT Linux 10 Distrobox, файловая база,
`dbgs` на loopback и графический клиент на отдельном дисплее. Путь к
проекту и базе содержал пробел и кириллицу. Rust-тесты подтвердили стоп
на строке 3, `A = 41`, `A + 1 = 42` в текущем кадре и `A + 2 = 43`
в вызывающем. Также проверены ошибка выражения, раскрытие структуры, отбрасывание
старой ссылки на переменные, удаление точки и продолжение. Сценарий повторён
с единственным профилем `prod` на собственной тестовой базе. Установленный
Explorer в VS Code 1.144.0 прошёл launch и attach с выбором существующего
предмета в русской и английской локалях. Клиент остался запущен после отключения.

Восемь отдельных release-процессов, одна и та же конфигурация. DAP замерен от
отправки запроса до ответа, для шагов — до подтверждения команды. HTTP замерен
отдельно до получения ответа `dbgs`, поэтому таблица показывает вклад протокола.

| Операция | Число замеров DAP | DAP median / p95, мс | HTTP median / p95, мс |
| --- | ---: | ---: | ---: |
| От старта процесса до initialize | 8 | 184,45 / 195,03 | — |
| launch | 8 | 1,44 / 2,46 | attachDebugUI 0,79 / 1,67 и setAutoAttachSettings 0,52 / 0,60 |
| stackTrace | 96 | 0,040 / 0,058 | — |
| variables | 96 | 10,39 / 100,57 | evalLocalVariables 10,33 / 10,85. Раскрытие обращается к evalExpr |
| evaluate | 104 | 100,64 / 101,30 | evalExpr 100,55 / 101,22, включая запросы раскрытия |
| stepIn | 8 | 20,69 / 25,89 | 20,63 / 25,76 |
| next | 8 | 20,84 / 21,41 | 20,72 / 21,33 |
| stepOut | 8 | 0,655 / 0,768 | 0,569 / 0,705 |
| continue | 8 | 5 002,80 / 5 003,70 | 5 002,67 / 5 003,62 |

В этой последовательности `dbgs` удерживал ответ на `continue` около пяти
секунд. В отдельном прогоне с `prod` ответ занял 21 мс. Это разница между
сценариями стенда, поэтому время `continue` нельзя переносить на другие
сеансы. В одном предварительном прогоне Evaluate получил ошибку. В итоговой
серии из восьми сессий она не повторилась. Пустой опрос может удерживаться дольше двух секунд. Отдельный поток
опроса и проверка живости позволяют обработать DAP в это время.

За 2 секунды простоя `/proc` не зарегистрировал прироста CPU-счётчика
(разрешение 10 мс). RSS и пик RSS перед отключением составляли 6 864–6 992 КиБ.
В отдельной серии из восьми подключений к одному уже запущенному клиенту,
с чередованием `disconnect` и EOF, RSS/пик составляли 6 816–6 864 КиБ.
Каждая сессия использовала новый процесс адаптера, который завершался после
отключения. Клиент пережил всю серию.

Release-бинарник `eska-debug` — 3 891 872 байта (3,71 МиБ).
VSIX — 4 557 813 байт (4,35 МиБ), установленные файлы — 9 954 277 байт
(9,49 МиБ), JS — 3 071 534 байта (2,93 МиБ). Сверены файлы установленного VSIX
и содержимое архива.

Активные зависимости `eska-debug` проверены через `cargo tree` с рёбрами
normal/build и features. HTTP использует стандартные сокеты Rust и `httparse`,
XML — `roxmltree`, сжатие в транзитивном дереве — `zlib-rs`. В нативном
бинарнике `ldd` показывает загрузчик ОС, libc и libgcc. Git-проверка запускает
существующий самостоятельный `eska-vcs` при необходимости. На стенде были
удалены временные артефакты прежнего C#-эксперимента, а `dotnet` и `mono`
отсутствовали в PATH.

### Раскрытие результата Evaluate

Адаптер передаёт в одном `evalExpr` выражение, новый `expressionID` и путь
к полю структуры с результатом. Платформа возвращает представление, тип
и метаданные результата. Если платформа опускает размер индексируемого
или перечисляемого значения, адаптер читает контекст сохранённого
значения отдельным запросом без чтения элементов. Для раскрытия он отправляет тот же
`expressionID`, пустой селектор выражения и путь к свойству или элементу.
В DAP-ссылке остаются идентификатор и путь. Пустой селектор без пути
на 1С 8.3.27.2342 не возвращает значение, поэтому путь начинается с поля
структуры. Платформа сохраняет результаты в текущей остановке.

На 1С 8.3.27.2342 подтверждены раздельное хранение результатов, страница
массива по индексу, повторное чтение вложенных свойств, вычисление в
вызывающем кадре и сброс ссылок после шага. `ЗаписьJSON` и `ЧтениеJSON`
проверены в тонком клиенте и в серверном кадре файловой базы через
`ServerEmulation`. Счётчик подтверждает однократный вызов на каждый
запрос Evaluate. На остановку одного предмета допускается до 256
вычислений, включая скаляры. Отправленные запросы с неопределённым
исходом учитываются в лимите до продолжения.

В отладочной сборке на Linux ARM64 240 раскрытий по три уровня заняли
73,08 секунды. RSS и пик RSS адаптера выросли с 12 304 до 12 352 КиБ.
Серия прошла после изменения HTTP-транспорта. В отдельном опыте на этой же
версии `dbgs` принял 20 из 20 запросов с цельным заголовком и вернул
HTTP 400 на 20 из 20 запросов с раздробленным заголовком. Адаптер теперь
формирует заголовок целиком перед отправкой.

В пяти релизных сеансах на Linux ARM64 RSS и пик RSS составили 7408–7472 КиБ.
За 2 секунды простоя счётчик CPU не изменился. Из 65 запросов Evaluate
медиана составила 101,34 мс, p95 — 104,71 мс. Запросы этой серии проверяли
скаляры и структуры. Для массива из 600 элементов отдельный прогон
проверил размер, вложенные ссылки и 24 повторных запроса по 100 элементов.
Медиана и p95 запросов страницы составили 102,87 и 104,83 мс.

### Условные точки, логпоинты и ошибки выполнения

Условие точки задаётся выражением 1С. Логпоинт принимает обычный текст и
выражения 1С в фигурных скобках, например `Сумма: {Сумма}`. Двойные фигурные
скобки выводятся как текст. Счётчик принимает положительное целое число
попаданий. При сочетании условия и счётчика учитываются попадания, для которых
условие истинно. Некорректные счётчик или шаблон получают статус
непроверенной точки с пояснением. Для событий с одним сообщением или обновлением
счётчика адаптер возобновляет выполнение. Парные события стека и ошибки,
полученные для одного предмета в одном ответе `dbgs`, дают одну остановку
с причиной `exception`.

VS Code показывает текст исключения в штатном виджете редактора. Адаптер
возвращает `exceptionInfo` для выбранного потока только во время остановки
на исключении. Продолжение, следующая остановка и выход потока сбрасывают
сведения о прежнем исключении.

На 1С 8.3.27.2342 проверены текст фильтрованного исключения и нового
исключения после смены фильтра. Установленный VSIX в VS Code 1.144.0 на
русском и английском показал сообщение `ESKA match` в штатном виджете
редактора. После Continue виджет исчез, запрос для потока на следующей
обычной точке был отклонён. Для повтора используется сценарий
`exception-info` с фикстурой `breakpoints.bsl` в `test/debug-http-host.cjs`.

Если при служебном Continue платформа возобновила другой остановленный
предмет, адаптер сбрасывает его кадры и ссылки на значения и отправляет
событие `continued`. На 1С 8.3.27.2342 это проверено с двумя клиентами.
Логпоинт второго клиента возобновил первый. Его следующая остановка
на обычной точке получила новый кадр, старые ссылки отклонены.

### Приложение с расширениями

Используйте `crates/eska-debug/tests/fixtures/application/base.bsl` для
управляемого модуля конфигурации. В той же временной базе создайте расширения
`One` и `Two` и выгрузите их в отдельные проекты Designer XML
`первое расширение` и `второе расширение`. Для проверки одновременной установки
дайте сгенерированным ролям уникальные имена в обоих XML-деревьях. Скопируйте
`one.bsl` и `two.bsl` в `src/Ext/ManagedApplicationModule.bsl` соответствующих
проектов, импортируйте их и примените к временной базе через `ibcmd config apply`
с `--extension`. Перечислите основной проект и оба расширения в одном приложении
в корневом `eska.toml`. Запустите тест
`native_maps_breakpoints_and_stack_across_the_application` с `ESKA_DEBUG_LIVE_PROJECT`,
указывающим на основной проект. Проверяются точки и пути в стеке для трёх
модулей и вычисление в кадре каждого расширения. Сценарий пройден на
1С 8.3.27.2342 через DAP и в установленном VSIX с VS Code 1.144.0.

В release-сборке после первого раскрытия диапазона из 100 элементов
24 повторных запроса сохранили те же значения и ссылки. Время DAP p50/p95 —
101,93/102,46 мс, HTTP `evalExpr` для тех же запросов — 101,52/102,09 мс.
RSS и пик RSS до серии — 7072 КиБ, после — 7104 КиБ. Это один прогон на
Linux ARM64, он не характеризует длительные сеансы и другие окружения.

### Что ещё отсутствует или требует доработки

1. **Полная инкрементальная запись конфигурации.** Частичный `apply` поддерживает
   существующие BSL, проверенные свойства и макеты Designer XML, добавление,
   удаление и переименование языков и общих управляемых форм с XML-макетом
   и необязательным модулем BSL, а также общих модулей с `Ext/Module.bsl`.
   Остальные структурные изменения требуют отдельного подтверждения
   полного импорта. Установленное расширение в области `InfoBase` обновляется
   отдельно в базе `test`. Для него частично применяются правки существующих BSL
   и свойств существующих ролей без отдельных ресурсов. Добавление,
   переименование по UUID и удаление с неизменённой ролью по умолчанию
   поддерживаются для собственных ролей без отдельных ресурсов и собственных
   общих модулей с `Ext/Module.bsl`. Остальные правки XML расширений требуют
   полного импорта исходников расширения.
   Для установки и удаления `InfoBase` есть отдельные подтверждаемые команды
   `extension install` и `extension remove` в CLI и Explorer. Область
   `DataSeparation` остаётся за пределами этого сценария. Standalone использует
   административный PID в выбранном локальном или Distrobox runner.
   Удалённого административного транспорта пока нет.
2. **Доставка компонента пользователю.** `eska-debug` собирается отдельно,
   Explorer умеет находить настроенный бинарник. Общий `eska debug`, включение
   в установку/обновление набора компонентов и выпуск ещё не выполнены.
   Release pipeline в этом ревью не изменялся.

В установленном VSIX на русском и английском Step Over проверен на двух
остановленных клиентах 1С 8.3.27.2342. Платформа возобновила оба предмета.
Адаптер отправил по одному событию `continued` на поток, снял оба старых
кадра и показал новый кадр выбранного потока.

В установленном Explorer 0.1.18 в VS Code 1.144.0 на русском и английском
отдельно проверены штатные действия редактора на 1С 8.3.27.2342. Наведение
мыши на `A` вызвало DAP Evaluate с контекстом `hover` в остановленном кадре.
В подсказке редактора появилось `41`. VS Code отправил снятие точки и
запросы Step Into, Step Over, Step Out и Continue для того же потока.
Первые три действия остановились соответственно на строках 9, 10 и 5
модуля `evaluate-snapshot.bsl`. Строка 5 — место вызова. Evaluate в
вызывающем кадре вернул `43`, а запрос к кадру завершившейся функции
получил ошибку. Сценарий `editor-controls` в `test/debug-http-host.cjs`
запускается через `test/run-host.mjs` с установленным VSIX,
`ESKA_HOST_NORMAL=1` и отдельным локальным портом `ESKA_HOST_DEBUG_PORT`.
Коммит Explorer `ba79c88`.

Тот же сценарий в установленном VSIX en/ru проверяет ввод
`ПолучитьСнимок()` в Debug Console, раскрытие мышью трёх уровней и повторное
открытие свёрнутого результата. В обеих локалях редактор показал `Номер = 1`.

`variables` для вложенных значений. Счётчик на стороне 1С остался равен
одному. После Step Into прежняя ссылка на результат была отклонена.
Коммит Explorer `75cd8d0`.

На Linux при прогоне в отдельном Xvfb запустите VS Code с
`XDG_SESSION_TYPE=x11` и `ELECTRON_OZONE_PLATFORM_HINT=x11`, убрав
`WAYLAND_DISPLAY` и `WAYLAND_SOCKET` из окружения стенда. Это направляет
ввод в изолированное окно теста.

Реальные remote/VPN, Windows/macOS и кластерные предметы требуют отдельной
приёмки. Возможность указать удалённый HTTP-адрес
уже есть; это не доказательство прохождения этих сценариев. TCP и обновление
кластерной базы остаются за границами согласованного этапа. Production по-прежнему
не допускает административный apply, но Evaluate намеренно разрешён и может
изменять данные. Сравнение исходников с реально установленным prod-кодом
согласованно остаётся ответственностью разработчика.
