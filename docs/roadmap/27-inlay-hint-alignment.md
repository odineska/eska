# T149 — Выравнивание многострочных аргументов при подсказках параметров

**Статус:** `DONE` — обычные подсказки параметров, Linux ARM64 / VS Code ru/en.
**Зависит от:** T86 — собственный LSP-клиент Explorer, выполнена.
**Владелец:** Explorer — отрисовка и жизненный цикл декораций;
ESKA — синтаксические границы строкового литерала.

Задача добавлена **2026-10-28**, выполнена в пуле **2026-10-31**.
Очередь — **T145 → T147 → T148 → T149 → T150 → T151**.
[Проверки и замеры](../measurements/t149-inlay-alignment.json).

## Поведение

Подсказка `Шаблон:` перед многострочным аргументом `СтрШаблон` сдвигает
первую строку и все её продолжения `|…` на одинаковую дополнительную ширину.
Сохраняется исходное относительное выравнивание. Работают другие вызовы,
вложенные вызовы и несколько последовательных многострочных аргументов.
Текст, окончания строк, dirty-состояние, настройки и история Undo не меняются.

При `editor.inlayHints.enabled = "on"` связанные подписи параметров и
прозрачные продолжения используют шрифт редактора и одинаковый padding.
Публичный attachment API не позволяет задать fontFamily/fontSize: прототип
показал расхождение 69,58 и 58,81 px между native-подсказкой с отдельным
шрифтом и такой же прозрачной вставкой. Поэтому используется общая отрисовка.
Учитываются все предыдущие подписи на строке открытия литерала;
независимые однострочные вызовы сохраняют штатный вид.

Подсказки с действиями, tooltip, text edits, составной подписью или resolve
сохраняют native-провайдер. В режимах `onUnlessPressed` / `offUnlessPressed`
и при явном `editor.accessibilitySupport = "on"` отступы не добавляются.
Публичный API не сообщает фактическую видимость подсказок по Ctrl+Alt.
Мягкий перенос и многострочные выражения вне строкового литерала не входят
в реализацию. Backend до API 1.34 сохраняет обычное отображение.

## Реализация

- Общий существующий BSL-сканер core определяет диапазон литерала и позиции
  продолжений. [Read-only API 1.34](../ide-protocol.md#api-134-геометрия-многострочных-bsl-литералов)
  получает точный снимок без пути и возвращает UTF-8 offsets с version/SHA-256.
  Лимиты текста, общего upload и числа продолжений проверяются backend и клиентом.
  Второго BSL-парсера в Explorer нет.
- Explorer преобразует проверенные границы в UTF-16 за один проход.
  Геометрия одного снимка используется split-вкладками; отмена одного запроса
  не прерывает другой. Ответы старой версии, документа или контекста отбрасываются.
- Правки и настройки очищают отступы до обновления подсказок. Закрытие,
  скрытие редакторов и остановка LSP освобождают стили. Неизменённые диапазоны
  повторно не передаются редактору при каждом viewport-запросе.

## Приёмка

`6694148` добавляет backend и тесты; `4ec6e66` в Explorer — отображение,
жизненный цикл и native-сценарий. Полный Rust-набор: **1396 passed,
18 ignored**, fmt/check/strict clippy успешно. Explorer: **417 passed,
10 skipped**, TypeScript и сборка успешно.

В настоящем VS Code 1.144.0 на Linux ARM64 с bsl-analyzer 0.4.2 выполнены
две матрицы по 16 комбинаций, отдельно в `ru` и `en`: тёмная/светлая тема,
два шрифта и размера подсказок, padding on/off, масштаб 0/1. Измерены позиции
реального исходного текста, а не только ширина decoration. Погрешность сдвига
первой строки и продолжений меньше одного CSS-пикселя во всех комбинациях.

Проверены BOM/CRLF, кириллица, табы/пробелы, кавычки, emoji, локальная функция,
вложенный вызов, два последовательных многострочных аргумента. Undo/Redo,
split, прокрутка, повторное открытие и перезапуск LSP проходят в обеих локалях.
Копирование содержит только исходный текст; системный clipboard тест не меняет.
Файл на диске сохраняется побайтно, показ подсказок не добавляет шагов Undo.

Native-проверка Windows, macOS и VSCodium не выполнялась. Для клавиатурной
приёмки использован XWayland: Wayland в этой среде не предоставлял окну
необходимый native-фокус. Это условие теста, настройки пользователя не менялись.
