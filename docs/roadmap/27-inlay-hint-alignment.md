# T149 — Выравнивание многострочных аргументов при подсказках параметров

**Статус:** `IN-PROGRESS` — прототип native-отрисовки после завершённой T148.
**Зависит от:** T86 — собственный LSP-клиент Explorer, выполнена.
**Владелец:** Explorer — визуальные отступы и жизненный цикл декораций;
ESKA / внешний анализатор — синтаксические границы строкового литерала.

Задача добавлена **2026-10-28**, включена в пул реализации **2026-10-31**.
Очередь — **T145 → T147 → T148 → T149 → T150 → T151**; T149 выполняется четвёртым этапом, после T148.
План реализации: сначала измерить native-подсказку и виртуальную вставку при разных
шрифтах, размерах и padding; затем выбрать отображение и подключить границы
литералов из общего backend. Реализация и приёмка ещё не завершены.

Прототип Linux/VS Code 1.144.0 подтвердил ограничение публичного API: native
подсказка с отдельным шрифтом и такая же прозрачная `before`-вставка имеют
разную ширину (69,58 и 58,81 px). У attachment нет fontFamily/fontSize.
Общая отрисовка подписи и продолжений совпадает по ширине; выбор отображения
и проверка полного жизненного цикла ещё выполняются.

Границы литералов добавлены в общий существующий BSL-сканер core.
[Read-only API 1.34](../ide-protocol.md#api-134-геометрия-многострочных-bsl-литералов)
принимает точный снимок без пути и возвращает byte ranges и позиции `|`,
привязанные к version/checksum. Использует общий ограниченный upload;
в Explorer не появляется второй BSL-парсер. Это самостоятельная подготовленная
часть T149, а не завершённая функция выравнивания.

## Сценарий и результат

В VS Code/VSCodium с ESKA Explorer подсказка `Шаблон:` перед аргументом
`СтрШаблон` сдвигает первую строку `"Найдено кандидатов: …`, а продолжение
`|Время выполнения …` остаётся на исходной позиции. Требуется одинаковый
дополнительный визуальный отступ для всех строк этого литерала с сохранением
их исходного относительного выравнивания.

Стандартный [InlayHint](https://code.visualstudio.com/api/references/vscode-api#InlayHint)
задаёт позицию подсказки, но не диапазон аргумента и не отступ его продолжений.
Кандидат для отображения — виртуальные вставки `before` через
[API декораций](https://code.visualstudio.com/api/references/vscode-api#ThemableDecorationAttachmentRenderOptions).
Точный способ отрисовки выбирается после прототипа в VSCodium.

## Границы и порядок работы

1. Проверить прототип: ширина виртуального отступа должна совпадать с полной
   отображаемой шириной подсказки, включая её padding. Учесть отдельный шрифт
   подсказок, размер, масштаб и тему. Если согласовать штатную подсказку и
   декорацию точно нельзя, проверить общую отрисовку подписи и отступов для
   таких аргументов, сохранив доступные действия подсказки.
2. Определить источник границ литерала по актуальному снимку документа:
   существующий синтаксический разбор ESKA либо согласованный контракт внешнего
   анализатора. Не создавать второй BSL-парсер в Explorer; необходимость
   расширения backend/LSP-контракта установить по результату прототипа.
3. Добавлять виртуальный отступ перед каждым продолжением `|…`, только пока
   показана соответствующая подсказка. Пересчитывать при правках и изменении
   настроек; очищать при скрытии подсказок, закрытии документа и остановке LSP.
   Устаревший ответ не должен оставлять отступы в новой версии текста.
4. Первый scope — многострочные строковые литералы с явными переводами строк,
   в любых вызовах с подсказками параметров, без привязки к `СтрШаблон`.
   Произвольные многострочные выражения и мягкий перенос редактора не входят
   в первую реализацию. Доработка не меняет BSL, пробелы, окончания строк,
   форматтер, сохранение файла или исходные настройки пользователя.

## Приёмка

- На примере пользователя `Шаблон:` одинаково сдвигает первую строку и все
  продолжения; проверены две и несколько строк, кириллица, табы/пробелы,
  экранированные кавычки и вызов внутри другого вызова.
- Отступ совпадает с подсказкой при разных размерах и шрифтах подсказок,
  масштабе, светлой/тёмной теме и настройке padding.
- Показ/скрытие подсказок, редактирование, Undo/Redo, split-вкладки, прокрутка,
  повторное открытие файла и перезапуск LSP не оставляют лишних отступов.
- Копирование возвращает исходный текст; показ декораций не делает документ
  dirty, не меняет файл на диске и не добавляет шагов Undo.
- Однострочные аргументы и строки вне целевого литерала сохраняют прежний вид.
- Тесты определения диапазонов и жизненного цикла дополнены нативной проверкой
  в Linux/VSCodium ru/en; остальные редакторы и ОС отмечаются по факту проверки.
