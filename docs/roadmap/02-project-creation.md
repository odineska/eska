# Project creation

## T82 — Создание и обновление из файлов 1С

**Статус:** `DONE`
**Зависит от:** T04, T06, T28, T48

Согласованный scope: `new <path> --from <file>` создаёт проект с определением
типа по выгруженному XML; `import <file>` обновляет standalone либо одного
workspace member (текущего или выбранного через `-p`). Типы: CF/CFE/EPF/ERF.
При создании standalone версия платформы выбирается явно и сохраняется;
workspace наследует корневую версию, явный выбор сохраняется у участника.

Обновление заменяет всё содержимое отдельного source-каталога, включая
посторонние файлы; `source = "."` не поддерживается. Настройки проекта и Git
сохраняются. Тип должен совпадать. Различие UUID или внутреннего `Name`, а также
незакоммиченные исходники требуют выбора «перезаписать / отменить»; без TTY
нужен явный `--force`. Пустой каркас можно заполнить после проверки типа.

**Готово:** создание standalone/workspace из изолированно распакованного файла,
bounded-проверка type/UUID/Name, сохранение версии платформы, общий runner и
существующий откат создания/enrollment. CF/CFE выгружаются деревом, EPF/ERF —
дескриптором и соседним каталогом; публикация приводит оба результата к source.

**Обновление:** `import` выбирает ровно один проект, сравнивает type/UUID/Name,
показывает область полной замены и предупреждения о другом объекте/локальных
исходниках. В TTY `y` или `д` подтверждает замену, а `n`, `н`, Enter, Esc и Ctrl+C
отменяют её. Вставка текста игнорируется. Без TTY или в JSON нужен `--force`.
Пустой каркас заполняется после проверки типа. Root-level source и ссылки отклоняются.
`--dry-run` показывает реальный результат распаковки без изменения проекта.

`ImportPlan` фиксирует исходники по SHA-256, config и состояние изменённых
source paths в Git. Перед публикацией выполняется повторная проверка. Старый
каталог переносится во временную копию, затем публикуется новый; обычная ошибка
публикации восстанавливает старый. Ошибка восстановления сохраняет копию и
показывает путь. Git index/refs и настройки не изменяются. Аварийное завершение
и конкурентная запись непосредственно во время переименования не входят в
транзакционные гарантии. Успешный импорт с ошибкой очистки сообщает путь остатка.

JSON v1 содержит текущую/входящую identity, source path с обратимым encoding,
имя участника workspace, число файлов/локальных изменений и признак применения. Ошибки содержат
стабильный код и подготовленный preview, когда он есть. Контракт описан в README.

Проверки: полный fmt/check/strict Clippy/test/Rustdoc; 557 тестов прошли,
6 существующих opt-in сценариев пропущены. Проверены ошибки распаковки,
rollback, параллельное редактирование исходников, типы/UUID/имена, source links,
workspace, locale-independent JSON и 12 PTY-сценариев RU/EN. Настоящая платформа
`8.3.27.2325` через Distrobox создала и повторно импортировала CF/CFE/EPF/ERF в
изолированном playground; EPF/ERF получены из минимальных XML через платформу.
Проверяется фактическое имя выгруженного XML, включая Unicode и точки в имени
исходного файла. Нативные Windows/macOS-прогоны здесь не выполнялись.

Уточнение от 2026-09-30: на настоящем CF воспроизведён отказ прямого
`config export --file` с ошибкой формата хранилища. CF теперь проходит
`create → config load → config export` во временной файловой базе; загрузка
и выгрузка исходного файла на `8.3.27.2325` успешны. CFE/EPF/ERF сохраняют
прямую распаковку. Тестовый runner отклоняет прямой CF export и проверяет
сохранность проекта при ошибке загрузки либо выгрузки. T82 остаётся `DONE`.

Временные данные и recovery-копии перенесены в `.eska/import/` рядом с
целевым каталогом (для ещё не созданных родителей — у ближайшего существующего).
Внутренний `.gitignore` исключает всё содержимое служебного каталога,
не меняя пользовательские правила. Проверены чистый Git status во время
распаковки, очистка ошибок, сохранение recovery-копий и отказ для ссылок
или пересечения source со служебным хранилищем. T82 остаётся `DONE`.

Диагностика `import` и `new --from` использует общий с `build`
`cli/process_output`: цвета уровней, индикатор работы и запись без лишних
переводов строк. Итоговая ошибка не дублирует уже показанный журнал. JSON
остаётся на stdout, диагностика — на stderr; `NO_COLOR` и перенаправление
отключают цвета. T82 остаётся `DONE`.

проекта теперь создаётся эксклюзивно до распаковки, временные файлы находятся

Проверки этого исправления: fmt/check/strict Clippy/Rustdoc успешны;

## T04 — `eska new`

**Статус:** `DONE`
**Зависит от:** T03, T05

Добавить создание нового проекта с интерактивным выбором type/workflow и
обязательным неинтерактивным режимом `--type` + `--workflow`. Предусмотреть
`--no-vcs`; не повреждать существующие файлы и не оставлять частичный проект при
ошибке. На этом этапе workflow preset сохраняется как выбранная конфигурация;
исполняемая policy появится в T08–T11.

**Результат:** `eska new <path>` создаёт каркас всех четырёх типов. В TTY
недостающие type/workflow выбираются в клавиатурном TUI; без TTY оба
флага обязательны. Help, prompts, сообщения результата и доменные ошибки
локализованы на RU/EN. Коды: `0` — создано, `1` — ошибка/отмена, `2` — параметры.

Preset `trunk`, `git-flow`, `github-flow` или `custom` сохраняется в необязательной
секции `[vcs.workflow]` с обязательным строковым `preset`. Старый минимальный
config остаётся валидным. Policy, дополнительные ветки и custom-настройки пока
не исполняются. `Template::from_config` использует общую сериализацию T02.

Core `project::create` выполняет preflight и эксклюзивно создаёт только новый каталог
с существующим родителем; любой существующий путь, включая пустой каталог и
висячую ссылку, отклоняется. Файлы открываются с `create_new`. При ошибке записи,
Git init или итоговой проверки T03 удаляется только созданный этим вызовом
каталог; ошибка очистки сохраняет исходную причину и путь для ручной проверки.
Аварийное завершение процесса и конкурентные внешние изменения не являются
транзакционными сценариями.

Узкий внутренний `vcs::git` helper инициализирует Git через `gix` без внешнего Git,
user/system config и перенаправляющих Git env. HEAD — `main` без commit, remote
и workflow-веток; `--no-vcs` отключает init, не удаляя preset из config.
Используется `gix 0.87.1` с выключенными default features и минимальным набором
`revision`, `sha1`, `status`. SHA-1 выбран явно для существующего формата Git;
zlib-rs подключается самим `gix` без отдельного feature. В `clippy.toml` разрешены
только неизбежные транзитивные дубликаты `bitflags`, `syn` и `hashbrown`; причины
указаны рядом, остальные проверки не ослаблены.

Проверки: 32 сочетания type/preset/locale; Git без system Git и изоляция env;
коллизии и symlinks; невалидные пути/параметры; config round-trip; отмена,
навигация и откат, включая ошибку самой очистки. Все CLI-тесты на этой
машине выполняются с `ESKA_TEST_ROOT` в внешнем playground. Ручные RU/EN проверки
также выполнены там. `init` реализован далее в T06; repository layer остаётся T07.

**Улучшение TUI:** вместо строкового ввода — стрелки, `j/k`, Home/End и `g/G`;
Enter подтверждает выделение, `1–4` выбирают сразу. Esc/Ctrl+C/Ctrl+D отменяют
создание. Выделение — маркер, bold и cyan; `NO_COLOR` отключает оформление.
`crossterm 0.29` используется только в CLI для событий и терминального режима,
с features `events`, `windows`, `bracketed-paste`, без async/clipboard/derive.
Guard восстанавливает raw mode, курсор и alternate screen при возврате,
обычной ошибке и unwinding. Принудительное завершение без unwinding (например,
SIGKILL) не гарантирует восстановление. Обрабатываются resize (минимум 50×14),
неизвестные клавиши, key release/repeat и bracketed paste. До завершения выбора
файлы не создаются. CLI-флаги, схема config, коды и stdout сохранены.
Unit-тесты покрывают управление и RU/EN-отрисовку; дополнительно проверены
настоящий PTY, восстановление его настроек, отмена обоих шагов, resize,
вставка, `NO_COLOR` и перенаправление stdout. Все запуски CLI — в playground.

**Раскладка клавиатуры:** добавлен ограниченный fallback стандартной русской
раскладки: `о/л/п/П` соответствуют `j/k/g/G`. Он находится в одном обработчике
навигации CLI и не зависит от locale, не преобразует текст и не затрагивает
Ctrl/Alt/Super. Новых dependencies и платформенных API нет. Это не универсальное
распознавание физической клавиши. [Kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/#key-codes)
передаёт base-layout key только при поддержке терминалом; `crossterm 0.29`
не предоставляет этот код приложению. Поддержка протокола с другим/доработанным
backend остаётся возможным дальнейшим улучшением, но не вводится как требование
к терминалу в этой задаче. Проверены эквивалентность событий, модификаторы,
repeat/release и навигация русскими клавишами в RU/EN TUI.

## T05 — Built-in templates

**Статус:** `DONE`
**Зависит от:** T03; технически реализуется перед завершением T04

Встроить минимальные шаблоны для четырёх project types. Генерировать только
необходимые `eska.toml`, source directory и обоснованные README/git files.
Внутренняя граница должна позволить позже добавить custom/company templates, но
remote registry сейчас запрещён.

**Результат:** `project::templates::Template::built_in(ProjectType)` формирует
locale-independent план каталогов и файлов для всех четырёх типов. Каждый план
содержит `eska.toml`, встроенные из `crates/eska-project-core/assets/project/` универсальные
`.gitattributes` и `.gitignore`, каталог `src/` и пустой `src/.gitkeep`, чтобы Git
сохранял исходный каталог до первой выгрузки XML. Config генерируется
сериализатором T02 из `ProjectConfig::new`, без дублирования схемы и явной записи
defaults. Известные бинарные форматы передаются в Git LFS, а служебные индексы
Designer XML исключаются из Git. Инициализация LFS и блокировки форм остаются
отдельным этапом VCS workflow.

План отделён от записи файлов: T04 использует его для preflight и
создания проекта с обработкой конфликтов и откатом. Это также внутренняя граница
для будущих local/custom/company templates; их загрузка и remote registry пока
не реализованы. Нет README, workflow и XML-заготовок внутри самого шаблона.
Каркас проходит T03, но пока не является готовой к импорту/сборке XML-выгрузкой
1С.

Проверки: состав, безопасные относительные пути, детерминированность, компактный
config и round-trip для всех типов; материализация в тестовых временных каталогах,
discovery и CLI на обоих языках. Production-запись файлов и команда
`eska new` реализованы отдельно в T04. Сам template layer не добавляет
dependencies и human-readable строк.

## T06 — `eska init`

**Статус:** `DONE`
**Зависит от:** T03, T05

Подключать существующую Designer XML выгрузку: безопасно обнаружить параметры,
спросить только неизвестные, создать config и опционально repository/workflow.
До T07 допустима только минимальная безопасная инициализация Git через единый
внутренний helper, который затем станет частью repository layer.

**Готовность этапа:** `new` и `init` в interactive/non-interactive сценариях
создают проект, который без специальных исключений загружается T03; collision и
rollback сценарии протестированы.

**Результат:** `eska init [path] [--source <relative>] [--workflow <preset>]
[--no-vcs]` подключает существующий каталог, не изменяя исходники. Путь по
умолчанию — текущий, `--project-dir` задаёт базовый каталог. Поиск ограничен
верхним уровнем корня и `src`; для нестандартной структуры используется
`--source`. Несколько каталогов требуют явного выбора; несколько корневых
дескрипторов в одном каталоге отклоняются. Ссылки разрешаются только внутри
корня, конфигурация сохраняет нормализованный относительный source.

Дополнение 2026-09-30: `init` использует тот же выбор установленной платформы,
что `new --from`, и сохраняет `[build].platform_version` до завершения
инициализации. Для standalone без TTY обязательны `--workflow` и
`--platform-version`. `--select-platform` открывает меню; параметры `--ibcmd`,
`--platform-arch`, `--distrobox` уточняют поиск. Проверяется точное соответствие
версии `ibcmd`, без создания базы или сборки. Отмена и ошибки выбора происходят
до записи config и Git-файлов.

В workspace `init` по умолчанию наследует версию корня без запуска платформы.
Явный выбор или незаполненная версия корня сохраняют member-level
`platform_version`; каталог артефактов и workflow остаются корневыми. Проверка
возможности включения участника выполняется до выбора платформы. Внутренний
`project::init::apply` теперь принимает валидированные `BuildSettings`, а
`WorkspaceInitPlan::with_build_settings` задаёт переопределение после preflight.

Проверки дополнения: полный fmt/check/strict Clippy/test/Rustdoc проходит,
586 тестов успешно, 6 явно пропущены. CLI-тесты покрывают RU/EN, сохранение версии,
наследование и переопределение, ошибки до записи и сохранность XML/Git-файлов.
14 PTY-сценариев RU/EN проверяют оба меню, отмену и восстановление терминала;
2 из них используют установленную 1С 8.3.27.2325 через Distrobox. Проверки
выполнены на Linux; Windows/macOS не запускались. T06 остаётся `DONE`.

Тип определяется из namespace-aware XML: `Configuration`, расширение с
`ConfigurationExtensionPurpose` в его `Properties`, `ExternalDataProcessor` или
`ExternalReport`. `ConfigurationExtensionCompatibilityMode` не используется как
признак расширения, поскольку встречается и в обычных конфигурациях. Корневой
элемент — `MetaDataObject` в `http://v8.1c.ru/8.3/MDClasses`. Поэтому `--type`
не требуется и не добавлен. В TTY запрашиваются неизвестный workflow и платформа;
без TTY они обязательны через флаги. Общий selector получил параметр заголовка и
единый список workflow, управление клавишами и fallback раскладки сохранены.
RU/EN help, результат, отмена и структурированные ошибки локализованы.

Core разделён на read-only `project::init::inspect` и `apply`; перед записью
выбранные исходники проверяются повторно. Используется общая схема config,
добавлен `ProjectConfig::with_source`, итог проверяется обычным discovery T03.
Общие с `new` `.gitattributes` и `.gitignore` создаются из встроенных assets,
только если соответствующий путь отсутствует; существующие файлы не читаются,
не объединяются и не перезаписываются. `.gitkeep` и XML-заготовки не добавляются.
Config создаётся с `create_new`; коллизия любого существующего `eska.toml` не
разрешает перезапись.

Новый `.git` эксклюзивно резервируется, затем наполняется через тот же узкий
helper `gix`, что у `new`, со staging внутри принадлежащего вызову `.git`.
Существующие локальные/родительские Git-репозитории и `.git`-файлы проверяются
без переинициализации и перезаписи. Git env не перенаправляет операции.
`--no-vcs` пропускает инициализацию репозитория, сохраняя preset и создание
отсутствующих Git-файлов. При обычной ошибке удаляются только собственные config,
`.gitattributes`, `.gitignore` и `.git`; корень, исходники и существующие файлы не
удаляются. Ошибка cleanup сохраняет исходную причину и оставшиеся пути.
Crash/concurrent external mutation не входят в транзакционные гарантии.
Полноценный repository layer — T07.

Для XML добавлен [roxmltree 0.21.1](https://docs.rs/roxmltree/0.21.1/roxmltree/):
в std и прежних dependencies XML-парсера нет; вместо собственной реализации
используется namespace-aware parser с минимальным feature `std` (без positions).
Единственная транзитивная зависимость `memchr` уже была в графе. XML читается как
UTF-8/BOM, DTD и внешние entities отключены; лимиты 64 МиБ / 1 000 000 узлов.
`ConfigDumpInfo.xml` не разбирается. Полная модель/семантика и проверка всех
объектов остаются T19; этот этап распознаёт только корневые дескрипторы.

Проверки: 120 тестов во всём проекте; среди них — 24 сочетания
type/location/locale, сохранность байтов исходников и существующего Git,
Git env, gitfile, bare, коллизии, malformed XML/DTD, лимит размера, неоднозначность,
symlink escapes, повторная проверка и rollback/cleanup failure. Полные fmt,
check, clippy с `-D warnings` и test проходят. Ручные RU/EN help и PTY-сценарии
init (одно меню, выбор, отмена, stdout и восстановление терминала) выполнены в
playground; повторно прошли 8 PTY-сценариев new. Проверено на Linux; нативные
Windows/macOS-прогоны в этой среде не выполнялись.
