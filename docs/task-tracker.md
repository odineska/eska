# Публичный трекер ESKA

[Задачи](https://github.com/odineska/eska/issues) ·
[Доска ESKA Development](https://github.com/orgs/odineska/projects/1)

Карточки и обсуждения находятся в GitHub Issues, оперативные статусы —
в GitHub Projects. Публичные задачи доступны для чтения; для создания обращения
и комментариев нужен аккаунт GitHub. Права на изменение кода для этого не нужны.

## Язык и оформление

Заголовки, описания и рабочие комментарии сопровождающих и агентов пишутся
на русском языке. Имена команд, бинарников, файлов, меток и технических
идентификаторов сохраняются без перевода. Сообщения программы цитируются
в исходном виде.

В задаче разработки указываются проблема, ожидаемый результат, границы работы,
критерии готовности и ссылки на спецификации. Для ошибки нужны также версия,
окружение, шаги воспроизведения и фактический результат.

Формы «Ошибка» и «Предложение» хранятся в `.github/ISSUE_TEMPLATE`.
GitHub показывает формы после их включения в основную ветку репозитория.
Формы добавляют метку `bug` или `enhancement`. Выбор компонента записывается
в описание; соответствующие метки назначает сопровождающий или агент при
разборе задачи. Автоматического назначения меток по выпадающему списку нет.

## Метки компонентов

| Метка | Бинарник | Область |
| --- | --- | --- |
| `cli` | `eska` | Общий вход и делегирование команд |
| `project` | `eska-project` | Проекты, метаданные, контекст и сервер IDE |
| `check` | `eska-check` | Структурная проверка XML и анализ BSL |
| `fmt` | `eska-fmt` | Форматирование BSL и запросов |
| `build` | `eska-build` | Сборка, распаковка, импорт и применение изменений |
| `vcs` | `eska-vcs` | Git, состояние, сравнение и сохранение изменений |

Назначаются все затронутые компоненты. Метка `cli` не заменяет остальные
метки: она нужна, когда меняется сам общий вход `eska`. Если компонент
пока не определён, его уточняют при разборе обращения.

Метки `bug`, `enhancement` и `documentation` обозначают вид работы.
Метка `blocked` означает блокировку: её причина и условие продолжения
должны быть указаны в задаче. Она не заменяет текущий статус работы.

## Статусы и приоритет

| Статус | Значение |
| --- | --- |
| Входящие | Обращение ожидает разбора и уточнения |
| Запланировано | Объём согласован, задача готова к началу работы |
| В работе | Идёт реализация |
| На проверке | Результат готов к проверке и приёмке |
| Готово | Критерии готовности выполнены и работа принята |

Поле `Приоритет`: `Высокий`, `Обычный`, `Низкий`. Приоритет назначается
при разборе задачи; он не разрешает расширять согласованный scope.
Отклонённые предложения и дубликаты закрываются с соответствующей причиной
и пояснением, а не объявляются реализованными.

## Работа агента

Перед созданием задачи проверить дубликаты и фактический код. Создавать задачи
только в рамках пользовательского запроса. Добавлять карточку Issue в проект,
назначать метки компонентов и согласованный статус. Не подменять Issue
черновой карточкой Projects: обсуждение должно оставаться доступным в Issue.

Поле `projects` в форме помогает добавить Issue в доску, если у автора есть
необходимые права. Для внешних обращений сопровождающий или агент проверяет
наличие карточки на доске и при необходимости добавляет её. Все новые Issues
доступны в списке задач репозитория независимо от доски.

Состояние Issue «открыта/закрыта» и поле `Status` в Projects — разные значения.
При переходах агент проверяет оба. Закрытие задачи и публикация комментария
выполняются в рамках поручения пользователя; переход «На проверке» сам по себе
не означает, что результат уже принят.

## Связь с существующим roadmap

Первичная настройка не переносит и не создаёт задачи. До отдельного переноса
существующие задачи `T…` и их статусы продолжают вестись в
[roadmap](roadmap/README.md) по [рабочему соглашению](roadmap/working-agreement.md).

При последующем переносе сохраняются номера `T…` и ссылки на исходные
спецификации. Для перенесённой задачи оперативный статус ведётся в GitHub;
документы сохраняют требования, архитектурные решения и результаты проверок.
Правила roadmap обновляются вместе с переносом, чтобы не вести две независимые
очереди задач.
