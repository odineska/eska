# Запуск и отладка 1С из Explorer

ESKA запускает клиент 1С и подключает отладчик прямо из VS Code / VSCodium.
Собственный `eska-debug` написан на Rust, общается с IDE по DAP, а с сервером
отладки платформы `dbgs` — по HTTP. .NET не требуется. Нативный TCP-режим
отладки 1С не поддерживается.

Это отдельная возможность от просмотра форм: просмотрщик показывает Designer
XML без исполнения BSL; отладчик работает с запущенной платформой 1С.
**Текущий этап работы с формами — только просмотр. Редактирование форм — в планах.**

## Подготовить проект

1. Обновите Explorer и инструменты ESKA. Команда **Обновить все компоненты ESKA и BSL Analyzer**
   устанавливает `eska-debug` и при обновлении старого полного комплекта.
   Перед обновлением завершите активные сессии отладки. Для нестандартной
   установки задайте `eska.explorer.debugExecutable`.
2. Откройте корень проекта с `eska.toml`. В дереве ESKA нажмите правой кнопкой
   на **Настройки проекта** и выберите **Настроить проект**.
3. В окне **Запуск и отладка** заполните профиль `test` или `prod`. Укажите
   тип и адрес базы, среду запуска, платформу и параметры HTTP-отладки.
   **Из списка 1С…** заполняет поля базы из списка на стороне extension host.
   Переключение профилей сохраняет отдельные черновики до закрытия вкладки.
   **Сохранить профиль** и **Отменить изменения** действуют на открытый профиль.
   Если снять флажок **Настроить этот профиль**, сохранение удалит его локальную запись.
4. Проверьте исключение `.eska/settings_local.toml` из Git. Этот файл принадлежит
   конкретному проекту; адреса баз не нужно переносить в общий `eska.toml`.
   В поле пароля указывается имя переменной окружения.

**Проверить настройки** использует текущие значения открытого профиля через
`eska-build probe --stdin`. Команда проверяет наличие тонкого клиента, файл
базы или доступность настроенных TCP-адресов. Проверка не сохраняет черновик
и не открывает сеанс 1С. Для запуска встроенного сервера отладки проверяется
наличие `dbgs` в выбранной среде.

Клиент может запускаться локально или через Distrobox. База может быть файловой,
автономной или кластерной; её адрес и адрес `debug.url` сервера отладки независимы.
Для удалённой базы, в том числе через VPN, укажите доступный HTTP-адрес `dbgs`.
Это подключение к уже настроенному серверу; ESKA не развёртывает удалённую 1С.

Для локальной файловой базы `debug.managed = true` запускает собственный `dbgs`
на `127.0.0.1` со свободным портом. Адаптер завершает этот сервер при отключении.
Для внешнего сервера задайте `debug.url`.

## Запустить или подключиться

| Действие Explorer | Результат |
| --- | --- |
| **Запустить тестовую базу** | Обычный запуск клиента по профилю `test` |
| **Запустить 1С с отладкой** | Выбор `test`/`prod`, подключение отладчика и запуск клиента |
| **Подключиться к серверу отладки 1С** | Выбор профиля и подключение к существующему предмету |
| **Выбрать предмет отладки 1С** | Выбор нужного предмета из доступных в текущей сессии |
| **Обновить тестовую базу** | Preview и подтверждённое применение исходников в `test` |
| **Обновить тестовую базу и запустить 1С с отладкой** | Применение в `test`, затем запуск с отладчиком |

Для запуска и отладки `test` должен быть настроен соответствующий профиль.
Для отладки `prod` профиль `test` не обязателен. Перед `prod` проверяются
исходники относительно основной ветки выбранного Git-flow; при расхождении
действие выбирает разработчик. Соответствие этой ветки реальному коду на сервере
остаётся на контроле разработчика.

Команды обновления конфигурации доступны только для `test`. Частичное применение
поддерживает определённые изменения существующих BSL, свойств и макетов, а также
некоторые структурные изменения. Неподдержанные изменения требуют отдельного
подтверждения полного импорта; универсальная частичная загрузка пока не заявляется.
Поддержаны файловая и автономная база; административное обновление удалённого
сервера и кластерной базы в этот сценарий не входит.
[Точные границы частичного применения](1c-http-debug.md#что-ещё-отсутствует-или-требует-доработки).

При первом обновлении основной конфигурации существующей файловой базы ESKA
может создать локальный снимок чтением базы. Для этого инструмент выгружает
применённую конфигурацию, сравнивает её с основной конфигурацией и повторно
проверяет поколение. Импорт XML и обновление базы при такой сверке не выполняются.
Поэтому проект из того же `.cf` или свежая выгрузка Конфигуратора в `src`
не требуют полного импорта только ради создания снимка. Если исходники
действительно отличаются, в предпросмотр попадают их отличия от базы.

Первичная сверка большой конфигурации может занять несколько минут.
Explorer показывает ход операции и позволяет её отменить. Последующие
обновления используют сохранённый снимок. Неприменённые изменения
Конфигуратора, недоступное чтение базы, повреждённый снимок и незавершённое
применение не обходят существующие проверки и подтверждение полного импорта.
Автоматическое создание снимка чтением пока не распространяется на расширения
и автономный сервер.

Перед подтверждением обновления Explorer открывает отдельную вкладку с полным
прокручиваемым списком изменений, без обрезания по количеству файлов. Объекты
и модули показаны в обозначениях `eska diff`. Закрытие вкладки, Escape и отмена
не применяют изменения. Если во время просмотра появились несохранённые правки,
обновление останавливается; сохранённые изменения повторно проверяет backend
по токену подтверждения.

JSON-ответы `eska-build apply` дополнены необязательным полем `display`.
Для одного проекта это словарь точных путей из плана с подписями
`{"ru-RU":{"label":"…","group":"…"},"en-US":{"label":"…","group":"…"}}`.
В предпросмотре приложения внешний словарь содержит имена компонентов.
Для неизвестного формата файла `label` сохраняет путь, а `group` равен `null`.
Обе локали передаются независимо от `--lang`; поле предназначено только для
отображения и не изменяет состав плана или его подтверждение. Без `display`
клиент показывает исходные пути.

На Windows список частичного импорта передаётся платформе Unicode-аргументами:
имена объектов на кириллице не зависят от кодировки стандартного ввода.
Если список превышает безопасный размер командной строки, предпросмотр
требует отдельного подтверждения полного импорта.

## Работать на точке останова

- Поставьте точку в BSL. Поддержаны условия, счётчики срабатываний, логпоинты
  и остановка по ошибкам с фильтром текста сообщения.
- Используйте Continue, Pause, Step Into, Step Over и Step Out. Стек открывает
  исходник соответствующего модуля конфигурации или расширения.
- Смотрите локальные переменные, Watch и значения при наведении на выражение.
  В Debug Console можно вводить свои выражения BSL в выбранном кадре стека.
- Раскрывайте результат и вложенные значения. Коллекции читаются порциями;
  раскрытие результата Evaluate повторно не выполняет исходное выражение.
- **Set Value** принимает выражение BSL для доступной переменной, свойства
  или индексированного элемента; возможность присваивания определяет платформа.
- Выбирайте предметы и типы автоподключения для текущей сессии.

Evaluate и Set Value доступны и в `prod`. Выражения выполняются в настоящей
сессии 1С и могут иметь побочные эффекты. Отмена ожидания не откатывает уже
выполненный код. После продолжения выполнения прежние ссылки на значения
и кадры перестают быть действительными.

## Внешние обработки и отдельный адаптер

Для проекта типа `processing` укажите собранный EPF в локальном профиле.
Рядом нужен манифест сборки: адаптер сверяет артефакт и исходники, а при запуске
открывает приватную копию EPF через `/Execute`. Подключение к уже загруженной
обработке использует её полный `debug_url`.
[Настройка EPF и ограничения](1c-http-debug.md#epf-в-проекте-explorer).

Можно использовать отладчик через Explorer либо как самостоятельный DAP-адаптер.
Отдельный ZIP `eska-debug-<version>-<target>.zip` опубликован в
[GitHub Releases](https://github.com/odineska/eska/releases/latest);
альтернативная установка — `cargo install --locked eska-debug`.
Самостоятельный вход — `eska-debug standalone`, без проекта ESKA и Explorer.
Нужен DAP-клиент; для VS Code есть минимальный декларативный пример расширения.
[Инструкция standalone](eska-debug-standalone.md).
