## Исправления

- Выбранная форма сохраняет читаемый заголовок: на Windows удалено наследование
  белого текста поверх светлого фона. Проверены светлая и тёмная темы VS Code
  в обеих локалях; контраст заголовка контролируется также для всех 97 форм.
- Rust-тесты протокола сравнивают физические пути через `Path`, без ожидания
  Unix-разделителей. Production-контракт путей не изменён.
- GUI-драйверы сопоставляют native-пути средствами ОС, включая регистр диска,
  обычные UNC и расширенное представление `\\?\`. Пути из `Uri.fsPath` и
  backend теперь определяют один источник в тестах композиции.
- Windows resize использует отдельный Win32-адаптер, ограниченный PID тестового
  Code: проверяются executable, класс, заголовок и геометрия окна. Linux X11
  helper на Windows не передаётся.
- Между формами закрывается CDP-соединение; наблюдение ждёт первой ревизии
  модели. Для изолированных Windows CDP-прогонов отключено фоновое ограничение
  renderer и увеличен ограниченный бюджет ответа. Удаление временных ресурсов
  допускает ограниченные повторы при Windows file locking.
- Responsive-сценарий учитывает существующую Windows-геометрию и HTML-таблицу
  табличного документа: проверяет видимость, 360 ячеек, изменение области и
  сохранение DOM. Строгие Linux-проверки растрового canvas сохранены.

Для каждого принятого результата JSON указывает конкретный batch и receipt.

Проверены несохранённый XML, Undo/Redo, внешние изменения, ошибочный XML и
восстановление последней модели, навигация, общая сессия основной вкладки и
отдельного окна, независимость нескольких форм, закрытие и восстановление.
Responsive-серия включает изменение настоящего окна Code, отдельного окна
просмотра, разделителей, размеров области и масштаба формы 100/125%.

Собственная галерея из 97 форм охватывает все 38 визуальных видов каталога.
Настоящая платформа импортировала её в `.cf`, загрузила и экспортировала обратно
в Designer XML. Все 97 форм после roundtrip открыты через реальный backend
на обоих языках и затем в установленном VSIX — 194 успешных открытия GUI.
Для каждой проверены три размера области, загрузка ресурсов, отсутствие
unsupported-элементов, сохранение DOM и исходных байтов. Хэши всех 203 файлов
выгрузки остались прежними. Отдельно прошли три сложные формы БСП ru/en.

Настоящая команда `eska build` успешно создала `.cf` через установленный `ibcmd`
в обеих локалях, в каталоге с кириллицей, пробелами и квадратными скобками.

## Что остаётся открытым

Строгие серии `renderer`, `states`, `groups`, `united`, `command-bars` и
`standardpictures` используют Linux native-метрики/растры и не приняты на
Windows. Их 12 результатов ru/en сохранены с ошибками; ожидания не заменялись
Windows-снимками самого Explorer. Импорт 1С и успешный GUI-прогон не доказывают
пиксельное совпадение с Конфигуратором.

Лицензия платформы активна, Конфигуратор открылся. Инструмент чтения его окна
возвращал `Computer Use was not approved to use 1cv8`; поэтому Windows-снимки
эталона не получены. Это ограничение инструмента, отдельно от работающего
CLI платформы. Проверки нескольких физических мониторов с разным DPI также
не выполнены. Масштаб формы 125% не считается проверкой аппаратного DPI.

Промежуточные ошибки путей, X11 helper, ожиданий Linux canvas, file locking,
ранней ревизии и CDP сохранены вместе с успешными повторами. Неудачный опыт
открытия многих отдельных профилей также сохранён: при нём наблюдалась высокая
нагрузка антивируса. Защитные настройки Windows не менялись. Итоговая галерея
прошла последовательно в одном профиле на язык.

## Воспроизведение и артефакты

Все временные данные находятся в соседнем `<eska>/../eska-playground`.
Уникальный каталог этой приёмки — `forms-windows-20261107-142029-38176c`;
каталоги `form-batch-*` с VSIX, backend, снимками, inputs и receipt перечислены
в JSON. Артефакты сохранены на стенде; в Git включены отчёт и их хэши.

Используйте `test/form-batch.mjs` из Explorer с `--eska-root`, `--backend`,
`--code`, `--cli-js`, `--ru-language-pack`, `--locales en,ru` и нужными `--suite`.
Для `application` также передаются `--application-project` и
`--application-samples`; в этой приёмке это собственная галерея после roundtrip
и список `native-all-samples.json` в каталоге приёмки. Пути определяются от
локальных корней репозиториев и установленной IDE. Полный Rust-прогон выполняется
с `ESKA_TEST_ROOT`, равным абсолютному пути соседнего playground.

Для ручной проверки на этом стенде подготовлен отдельный профиль: запустите
Open-Windows-Forms.ps1 из каталога приёмки (по умолчанию ru, параметр
-Language en переключает язык). Он открывает собственную галерею с
установленным проверенным VSIX и шестью бинарниками в соседнем bin.
Проверены все 1262 runtime-файла установленного расширения.
