# Вертикальная раскладка подвала в Linux

Конфигуратор 8.3.27.2342, интерфейс «Такси», Linux ARM64, 96 DPI,
масштаб 100%, совместимость 8.3.27. В пяти сериях сохранено 132 кадра
для 66 состояний на русском и английском. Контрольные формы загружены
из Designer XML и выгружены обратно. После съёмки проверены хеши
исходных и выгруженных XML. Координаты отсчитываются от внешней рамки
предпросмотра. Граница многострочного поля включена в измерение.

## Выравнивание групп

Подписи в одной группе с многострочным полем выравниваются по его
фактической высоте. Отдельная соседняя группа с полями надписей
ориентируется на предпочтительную высоту поля до растяжения. При
`Top` и стандартном `Auto` верх соседней группы привязан к началу поля
вместе с подписью. При `Center` и `Bottom` выравнивание использует центры
значений полей надписей. У каждой группы своя высота полосы подписей,
поэтому перенос в одной группе сохраняет высоту однострочной подписи
в другой. Явное выравнивание соседней группы сохраняет приоритет.

При `Bottom` в ряду с автоматической высотой соседняя группа может
потребовать дополнительное место ниже предпочтительной границы поля.
Рендерер учитывает это место при измерении минимума и перераспределяет
завершающий отступ поля. В широкой форме это сохраняет высоту подвала
без лишнего пикселя прокрутки.

| Состояние | Поле, Y / высота, px | Группа итогов, Y / высота, px |
| --- | --- | --- |
| `TallStretch`, `MaxHeight=4`, `Bottom` | 188 / 107 | 256 → 204 / 40 |
| `TallCenter`, `MaxHeight=4` | 123 / 107 | 119 / 40 |
| `TallTop`, `MaxHeight=4` | 58 / 107 | 39 / 40 |
| `ShortHeight`, высота формы 180 px | 60 / 107 | 76 / 40 |
| `Wrapped`, рамка 1094×127 px | 58 / 56 | 74 / 40 |
| `Wide`, рамка 1434×122 px | 58 / 51 | 74 / 29 |

Последние значения в таблице совпали с Конфигуратором. В `Wide`
совпали полные прямоугольники `Memo`, `Amount` и `Summary`. В `Plain`
снятие заливки возвращает высоту `Memo` к 51 px. У `TallStretch` размеры
по горизонтали пока различаются. Переключение выравнивания, ширины,
пределов и заливки проверяется через несохранённый XML в отдельном окне
с сохранением выбранного элемента и DOM предпросмотра.

## Stalingrad

На исходной форме «Поступление на счёт текущих расчётов» измерены
`Комментарий` и `ГруппаИтог`. Прямоугольники записаны в порядке
X / Y / ширина / высота, в пикселях.

| Рамка | Поле в Explorer до | Поле в Explorer после | Поле в Конфигураторе |
| --- | --- | --- | --- |
| 1430×726, широкая | 13 / 662 / 511 / 51 | 13 / 659 / 511 / 55 | 13 / 659 / 511 / 55 |
| 994×758 | 13 / 694 / 263 / 51 | 13 / 690 / 263 / 56 | 13 / 688 / 257 / 57 |
| 646×760, конец прокрутки | 13 / 696 / 127 / 51 | 13 / 692 / 127 / 56 | 13 / 692 / 127 / 55 |

В широкой рамке тело занимает доступные 649 px, итоговая группа
начинается на Y=687 и занимает 283×27 px. При 994×758 px `Описание`
сохраняет нативный прямоугольник 151 / 484 / 211 / 80 px. При 646×760 px
полный ход прокрутки тела вырос со 100 до 104 px, как на нативных
снимках. В конце прокрутки Y итоговой группы отличается на 1 px.
Исходные XML форм «Выдача займа», «Поступление на расчётный счёт»
и «Поступление на счёт текущих расчётов» проверены в 16 состояниях.
В первых двух формах размеры и положения контролов и ход прокрутки
совпали с предыдущим VSIX в проверенных состояниях.

## Оставшиеся расхождения

Горизонтальное распределение места в подвале при средних ширинах
требует дальнейшей сверки. При рамке 1083×729 px `Комментарий` получает
5 px дополнительной высоты, а `Описание` занимает 53 px вместо прежних
57 px. В этом замере низ кадра Конфигуратора был обрезан. Полная рамка
измерена отдельно вместе с исправлением `TallFixedDetails` и `MaxHeight=2`.
