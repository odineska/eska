# Порог сворачивания страницы при сквозном выравнивании

Конфигуратор 8.3.27.2342, «Такси», Linux ARM64, 96 DPI, масштаб 100%,
совместимость 8.3.27, русский язык. Измерены три серии из 55, 47 и 31 форм
после импорта и повторной выгрузки Designer XML. Рамка измерялась по чёрному
контуру, расположение полей — по цветным областям значений.

## Повторение замера

Основа — `IsolatedCaption39.xml`. Для всех вариантов с соседним полем задайте
`Connection.ThroughAlign=Use`. В таблице `Access` означает одинаковую замену
обоих языковых вариантов подписей у `NameInput`, `Password` и `Port`.
Остальные свойства берутся из основы. Для сравнения без соседнего поля
оставьте в корне только `Pages`, переключите `Page.Group` на `Horizontal`
и уберите `Width` у формы. [Исходный XML](../../tests/fixtures/forms/native-page-captions/IsolatedCaption39.xml).

## Что различает варианты

В EqualC23 и LongC23 логический прямоугольник `Connect` имеет X=229 и
ширину 173 px. В обоих случаях общая колонка подписей занимает 211 px.
Текст `Connect` влияет на решение о переносе при одинаковой геометрии
области значения. В BaseA191 и BaseA192 переход наблюдается между
логическими ширинами поля 191 и 192 px.

Для непереносимых подписей результаты согласуются с вычитанием прироста
сквозной колонки из доступной ширины ряда. Автоматическая ширина отдельной
страницы равна 317 px без полей рамки. При ширине 390 px и общей колонке
211 px собственные подписи 137 и 138 px оставляют соответственно
316 и 317 px. Варианты с меньшим `Width` у `Connect` и без кнопки выбора
также складываются при подписи 137 px и остаются в ряду при 140 px.
Увеличение ширины `AgentPort` на 20 px сдвигает проверенный переход
в область между 151 и 158 px.

Для переносимой подписи требуется определить ширину её собственной
колонки на этапе проверки ряда. При `AgentPort.Width=7` одна и та же
логическая ширина `Connect` 203 px даёт колонку при рамке 424 px и ряд
при 454 px. Принудительный ряд без соседнего поля размещается в рамке
176×94 px с подписями над полями и ширинами значений 71 и 61 px.

Установленный VSIX из `15fecf1` с `eska-project` 0.27.1 повторил
расположение полей в 43 из 55 и в 32 из 47 случаев первых двух серий.
В остальных случаях он оставил поля в ряду. Третья серия проверена
в Конфигураторе. [Ранее измеренная серия](t157-isolated-caption-layout-linux.json).

## Непереносимые подписи

Проверка ряда учитывает разницу между шириной общей колонки и собственной
колонкой группы с полем `Connect`. Координаты полей страницы определяет
её собственная компоновка. Правило проверено для страниц без вкладок,
верхних и нижних вкладок, условного ряда во вложенной группе без оформления,
двойного промежутка между полями и второго соседнего поля.

| Представление | Ширина рамки | Колонка → ряд по ширине подписи |
| --- | ---: | ---: |
| Без вкладок | 424 px | 137 → 138 px |
| Без вкладок, вложенная группа | 424 px | 137 → 138 px |
| Верхние и нижние вкладки | 424 px | 159 → 160 px |
| Верхние вкладки | 434 px | 149 → 150 px |

Проверки на установленном VSIX сравнивают предпочитаемую рамку и точные
прямоугольники полей. При изменении ширины и несохранённой подписи проверяется
обратный переход, в том числе в отдельном окне.
[Контрольные формы](../../tests/fixtures/forms/native-page-captions/README.md).

## Боковые вкладки

При кегле 10 pt вкладка «I» занимает 49 px с учётом стыка с рамкой страницы.
Проверка горизонтального ряда учитывает 43 px. Для заголовка «Page» при
такой же видимой ширине проверка использует 45 px. Максимальная ширина всей
панели равна сумме номинальной ширины полосы и максимума страниц с их
отступами. При ширине формы 674 px панель с вкладкой «I» занимает 631 px,
а с вкладкой «Page» — 633 px. При более узкой форме панель сжимается.

| Кегль, pt | Минимальная видимая полоса, px | Минимум для проверки ряда, px |
| ---: | ---: | ---: |
| 8 | 49 | 37 |
| 10 | 49 | 43 |
| 12 | 58 | 57 |
| 14 | 69 | 68 |
| 16 | 75 | 74 |
| 18 | 85 | 84 |
| 20 | 92 | 91 |
| 24 | 108 | 107 |
| 28 | 127 | 126 |
| 32 | 148 | 147 |

Для заголовка «Page» переход от колонки к ряду наблюдается при изменении
ширины соседней подписи 204 → 205 px в рамке 424 px. Для левых вкладок
при 434 px граница проходит между 194 и 195 px. В форме без сквозной
колонки при ширине рамки 424 px собственная подпись поля шириной 50 px
оставляет ряд, а 51 px переводит поля в колонку.

При смешанных кеглях 10 и 14 pt полоса получает отступы для большего
кегля, а ширина каждой подписи измеряется её шрифтом. Если полоса выше
фиксированного ряда, ряд сохраняет верхнюю координату. В измеренных
случаях страница без элементов пропускается при построении боковой полосы.

## Переносимая подпись при сквозном выравнивании

В новой серии из 82 форм подпись `Connect` — «Подключение к кластеру
серверов». В исходной форме без вкладок при рамке шириной 424 px изменялось
свойство `Connect.Width` и одинаковые подписи трёх полей группы `Access`.
За счёт изменения сквозной колонки менялась фактическая ширина `Connect`.
В таблице приведены соседние по замеру состояния с колонкой и рядом.

| `Connect.Width` | Ширина области значения с кнопкой при переходе, px |
| ---: | ---: |
| 16 | 159 → 160 |
| 18 | 179 → 180 |
| 20 | 179 → 180 |
| 22 | 179 → 181 |
| 24 | 189 → 192 |
| 26 | 191 → 192 |

Контрольные формы с `ThroughAlign=DontUse` сохраняют ту же подпись и
настройки поля. При `Width=18` и рамке 424 px собственная колонка подписи
занимает 161 px, при `Width=20` — 153 px. Измеренная ширина уже
нарисованной подписи в этих контрольных формах не воспроизводит общий
порог 179 → 180 px. Расчёт сворачивания для такой сквозной колонки
остаётся отдельной задачей.

## Принудительный горизонтальный ряд на странице

Для `Page.Group=Horizontal` и `AlwaysHorizontal` проверены страницы без
вкладок, с верхними и с боковыми вкладками. При ширине области полей 220 px
автоматические подписи «Адрес» и «Порт» находятся сверху. При 230 px они
находятся слева. При той же ширине 230 px замена подписи «Адрес» на подпись
шириной 45 px сохраняет боковое положение, при 46 px обе автоматические
подписи перемещаются наверх.

Для страницы без вкладок минимальная рамка составляет 176×94 px.
В неё входят поля шириной 71 и 61 px с промежутком 10 px. Явное положение
`TitleLocation=Left` сохраняется при сужении, а заданная ширина числового
поля учитывается до распределения места в ряду. Когда длинные подписи
переходят наверх, минимальная ширина колонки учитывает самое длинное слово.
Дополнительная ширина распределяется пропорционально этим минимумам с
учётом верхней границы каждой колонки. Последние строки верхних подписей
выравниваются по общей линии.

Отдельная серия из 21 формы с двумя длинными боковыми подписями показывает,
что ширины обеих подписей меняются вместе при перераспределении места.
Для воспроизведения изменяйте корневой `Width` в `ForcedPageBothWrappedAbove`
от 30 до 50. В таблице X и ширина области значения включают границу поля.

| `Width` | Рамка, px | `Address`, X и ширина | `AgentPort`, X и ширина |
| ---: | ---: | ---: | ---: |
| 30 | 334×97 | 77, 75 | 252, 61 |
| 33 | 364×97 | 78, 103 | 282, 61 |
| 37 | 404×82 | 113, 106 | 322, 61 |
| 45 | 484×82 | 109, 161 | 402, 61 |
| 50 | 534×82 | 127, 193 | 452, 61 |

Сверка в VS Code 1.109.0 с `eska-project` 0.28.0 и установленным VSIX
SHA-256 `25e41974aaf725c9b15034927d358f17de0ac90c0843fb006f6ba764f4b99a64`
подтвердила предпочитаемую и фактическую рамки во всех 81 состояниях.
Прямоугольники обоих полей совпали в 59 из 60 основных состояний и в одном

### Разделитель при переносе автоматических подписей

В серии из 65 форм проверены автоматические и явно заданные подписи, обратный
порядок полей, запрет растяжения числового поля, верхние и боковые вкладки.
В эталоне с двумя длинными автоматическими подписями разделитель отсутствует
на минимальной рамке 199 px, виден при 204–324 px и исчезает при 334 px,
когда подписи возвращаются сбоку. Короткая подпись числового поля оставляет
его колонку фиксированной, и разделитель отсутствует. Явная позиция слева
у одной подписи также сохраняет ряд без разделителя в измеренных вариантах.

При боковых вкладках Конфигуратор выбирает положение подписей с учётом
номинальной ширины полосы. В `ForcedPageDividerSideFits` остаются боковые
подписи, хотя фактическая область полей на 6 px уже расчётной. Тот же
поправочный размер используется при проверке сворачивания условного ряда.

В Explorer общий механизм разделителей ограничивает движение минимумами
и максимумами двух колонок. После перетаскивания или клавиши Home/End
пересчитываются ширина колонок и переносы подписей. Положение локально для
окна предпросмотра и восстанавливается при возврате к ширине, где можно
двигать разделитель.

С установленным VSIX SHA-256
`a327e2410225c12e132475415f1a5b237dd8ca3c1f84631831cd01fdbfc3be66`
видимость совпала в 62 из 65 состояний. У 32 видимых в обоих просмотрах
разделителей совпали координаты, высота и все 1959 пикселей полосы.
Сценарий `page-captions` прошёл в русском и английском VS Code 1.109.0
с `eska-project` 0.28.0.

Явная верхняя позиция имеет отдельный порог и другое распределение ширины.
Например, при рамке 234 px ширина строкового поля составляет 101 px против
87 px при автоматическом переносе. В дополнительной серии из 30 форм
обеим подписям задано `TitleLocation=Top`, а у `Address` меняется `Width`.
В последней колонке записаны измеренные рамки с разделителем и без него.

| 8 | 99 | 91 | 244 → 264 |
| Авто | 101 | 89 | 314 → 324 |
| 24 | 102 | 88 | 384 → 414 |
