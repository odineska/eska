# Приёмка ESKA на платформе 8.5.4

25 ноября 2026 года проверены локальные сборки ESKA 0.35.1 и Explorer
0.1.28 с VS Code 1.144.0 на Linux ARM64. Платформа 8.5.4.2072 работала
в отдельном Distrobox ALT 10. Прикладные проверки использовали копии
демонстрационного приложения 2.0.0.21 и собственные минимальные базы.
Выгрузка демобазы содержит `Version8_5_1` для совместимости и
`Version8_5` для интерфейса. BSL проверен с локально собранным
bsl-analyzer-app 0.4.7 и HBK 8.5.4.2072.

Геометрия интерфейса 8.5 проверена на Linux при 96 dpi и масштабе 100%.
В первичную сверку вошли верхние вкладки, ширина нескольких подписей
отличалась на несколько пикселей. 26 ноября измерили четыре значения
`PagesRepresentation` при двух ширинах, включая импорт старых значений
для нижних и правых вкладок.
[Дополнительная проверка вкладок](../roadmap/30-managed-form-preview.md#вкладки-при-изменении-ширины-и-темы).
Для «Такси» прошла живая регрессия переключателей. Контроль полной картинки
формы с тенью в наборе `tab-borders` дал один и тот же SHA-256 до и после
изменений 8.5. На этом дисплее он отличается от сохранённого эталона.
Конфигуратор показал свойство аналитической схемы отчёта
без доступного выбора, поэтому Explorer сохраняет и показывает ссылку.
Каталог глобальных имён bsl-analyzer 0.4.7 относится к 8.3.27. На целевой
8.5.4 ограничены диагностики отсутствующих имён и автодополнение новых
глобальных функций. [Проверка анализатора](../analyzer-configuration.md).

## Время открытия свойств метаданных

На копии той же демобазы сравнили release-сборки до и после индексации каталога.
Один процесс `eska-project serve --stdio` обслуживал запросы `metadata/propertyEditing`
для каждой локали. После первого запроса измерили медиану 31 повторения на одном
ядре Linux ARM64. Время включает передачу ответа и разбор JSON клиентом.

| Объект | Полей | До, мс (ru-RU) | После, мс (ru-RU) | До, мс (en-US) | После, мс (en-US) |
| --- | ---: | ---: | ---: | ---: | ---: |
| Конфигурация | 95 | 36,07 | 2,22 | 36,04 | 2,20 |
| Справочник «Товары» | 202 | 68,45 | 4,31 | 72,25 | 4,21 |
| Отчёт «Динамика продаж» | 13 | 5,35 | 0,62 | 5,51 | 0,62 |

Для всех трёх объектов SHA-256 содержимого JSON-ответов до и после изменения совпал в обеих локалях.

## Дополнительные проверки Explorer 26 ноября

На X11 при 120 DPI VS Code 1.144.0 проверил форму товара с эффективным DPR 1,25.
Для каждой локали пройдены 48 сочетаний четырёх значений `PagesRepresentation`,
двух размеров окна, двух тем и масштабов предпросмотра 75%, 100% и 125%.
При удлинении предыдущей подписи ширина и высота полосы сохранялись, но
выбранная вкладка уходила за край. После исправления горизонтальная
прокрутка вкладок сместилась с 196 до 244 CSS px. Прокрутка самой формы
сохранилась, XML после проверки совпал побайтно. В Конфигураторе на отдельном
X11-дисплее с 120 DPI полоса и строки остались 34 и 44 физических px
после сохранения настройки предпросмотра 125% и повторного открытия формы.
Физический масштаб Конфигуратора на этом стенде остался 1,0. Исходные замеры
в `native-tabs-dpi120.1w0qwn4m/measurements.json`, данные Explorer до и после
в `tabs-dpi120.MIgHm1Z2`. [Редактор форм #239](https://github.com/odineska/eska/issues/239).

На отдельной форме в VS Code 1.144.0 проверены автосохранение ширины поля,
создание процедуры `ПриОткрытии(Отказ)`, привязка `OnOpen` и побайтные
Undo/Redo ширины и привязки. Explorer сохранил неизвестную XML-секцию.
Импорт, применение и обратная выгрузка на 8.5.4.2072 сохранили ширину,
привязку и процедуру. Платформа опустила неизвестную секцию и нормализовала
кодировку и переводы строк BSL. Тонкий клиент выполнил процедуру после
открытия формы. В контрольном прогоне удаление одной привязки предотвратило
выполнение при том же BSL. Протоколы в
`audit239-native-7zeoh5jt/{result,native-roundtrip,runtime-result,runtime-negative-result}.json`.

В обеих локалях реальный VS Code подтвердил выбор установки Distrobox в черновике
профиля, диагностику окружения, просмотр плана без создания выходного файла,
сборку и повторную сборку CF. Общий тест команд Explorer прошёл на четырёх
проектах с выходными файлами CF, CFE, EPF и ERF. Семантическое сравнение двух
коммитов сохранило рабочее дерево Git. Полная проверка с bsl-analyzer-app
0.4.7 показала результаты в панели «Проблемы». Предпросмотр форматтера реагировал
на смену пресета и параметров черновика. Отмена сохранила байты BSL и
`eska.toml`. Протоколы в
`commands-854-4_4oofw8/{acceptance-summary,formatter-acceptance-summary}.json`.
[Команды проекта #347](https://github.com/odineska/eska/issues/347).

В завершающем прогоне #347 в VS Code 1.144.0 форма профиля в обеих локалях
подставила версию, источник и путь к `ibcmd` для 8.3.27.2342 на хосте и
8.5.4.2072 в Distrobox. Выборы сохранились в черновике. После сборки CF
локализованное действие открыло каталог `build` в Nautilus и передало путь
к созданному артефакту. Сравнение из меню панели «Изменения 1С» показало
добавленную BSL-процедуру из второго коммита и сохранило состояние Git.
Протоколы в `review347-final-WrG9Xd/{en,ru}/{receipt,evidence}.json`.

При создании проекта из EPF выбор установки Distrobox передаёт её контейнер и
путь к `ibcmd`. Общий механизм выбора платформы проверяет указанную пару внутри
контейнера. На 8.5.4.2072 CLI создал проекты с точной версией и с линейкой
`8.5.4`. В обоих вариантах в Designer XML сохранились имя и UUID обработки.
Проверка отсутствующего контейнерного пути завершилась с кодом 1 до создания
целевого каталога. Через приветствие VS Code в ru-RU и en-US мастер создал
проекты с одинаковыми XML, workflow Trunk и выбранной сборкой 8.5.4.2072.
Целевые каталоги появились после подтверждения. Протокол CLI в
`tabs-dpi120.MIgHm1Z2/native-cli-onboarding.json`, мастер в
`commands-854-4_4oofw8/onboarding/after-fix-summary.json`.
В отдельном прогоне план сборки с `--ibcmd` в Distrobox выбрал
8.3.27.2342 для требования `8.3.27`. JSON плана совпал в обеих локалях.
Протокол в `tabs-dpi120.MIgHm1Z2/legacy-selection.json`.

В английском интерфейсе мастер также создал каркас обработки, подключил
готовый Designer XML и клонировал локальный проект. Каркас с Trunk и 8.5.4.2072
появился после подтверждения. Подключение записало манифест после подтверждения
и сохранило байты исходников. Клонирование создало каталог после подтверждения,
сохранило HEAD и копию исходников. Протоколы в
`commands-854-4_4oofw8/more-onboarding/{new-acceptance-summary,acceptance-summary}.json`.

В двух локалях Explorer создал документы из корневой коллекции сразу с нужным
видом. Для каждого документа предложены модуль объекта и модуль менеджера.
Созданная роль исчезла из списка. Импорт и обратная выгрузка на 8.5.4.2072
в собственной базе сохранили оба документа и все четыре BSL-модуля.
Протоколы в `context328-854-uih42u5_`.

Дополнительная проверка #328 в VS Code 1.144.0 подтвердила создание реквизита
