# Предел высоты многострочных полей в Linux

Конфигуратор 8.3.27.2342, «Такси», Linux ARM64, 96 DPI, масштаб 100%,
совместимость 8.3.27. Серии из 22, 11 и 4 форм импортированы и выгружены
через Designer XML. Для ru и en сохранены 74 кадра с одинаковыми
размерами рамок и полей. Исходные и выгруженные XML проверены по SHA-256
после каждого запуска. Прямоугольники поля измерены по однотонной
заливке и границам, координаты отсчитываются от внешней рамки.

При заданной высоте многострочное поле с ручным пределом использует
те же единицы, что и его обычная высота. В профиле 10 pt первая строка
занимает 23 px, каждая следующая добавляет 28 px. При растяжении
горизонтального ряда ограничивается вся рамка поля с подписью.
Её позицию задаёт вертикальное выравнивание группы.

В контрольной форме с рамкой 1094×308 px поле занимало 237 px при
заданном `MaxHeight=4`. После исправления его высота составляет 107 px,
а верхняя координата переместилась с 58 до 188 px, как в Конфигураторе.
У отдельного поля при том же ограничении совпал весь прямоугольник
13/58/511/107 px, прежняя высота составляла 100 px.

| Настройка контрольного ряда | Высота поля, px | Y Конфигуратор / Explorer, px |
| --- | ---: | ---: |
| Две строки, Bottom | 51 | 239 / 244 |
| Три строки, Bottom | 79 | 216 / 216 |
| Четыре строки, Bottom | 107 | 188 / 188 |
| Пять строк, Bottom | 135 | 160 / 160 |
| Четыре строки, Top | 107 | 58 / 58 |
| Четыре строки, Center | 107 | 123 / 123 |
| Четыре строки, Bottom, 14 pt | 158 | 137 / 137 |
| Автоматический максимум, Bottom | 237 | 58 / 58 |

Для двух строк положение расходится на 5 px. При четырёх строках
в том же вложенном ряду ширина поля пока отличается на 4 px, а верх
окрашенной группы итогов остаётся на Y=256 вместо Y=203. Эти различия
относятся к распределению места между соседними группами. Расчёт
единиц `MaxHeight` в этом срезе подтверждён для явной высоты.

При заданной высоте обычной группы совпали высота и Y поля в трёх
из четырёх случаев. Для `MaxHeight=3/4` прежние 237 px заменены на
79 и 107 px. При заданной высоте промежуточной группы поле выросло
с 80 до 107 px. В тесной группе с `Height=4` совпал Y=58, обе сборки
Explorer показывают поле высотой 45 px при 54 px в Конфигураторе.

## Stalingrad

В исходном «Поступлении на счёт текущих расчётов» при рамке 994×758 px
прямоугольник «Описания» составляет 151/484/211/80 px. Пробное применение
новых единиц в автоматической раскладке увеличивало это поле до 86 px
и смещало нижние поля. Поэтому поправка применена при явно заданной
высоте формы или группы. При той же рамке «Комментарий» занимает 51 px
в Explorer и 57 px в Конфигураторе. При ширине 646 px в конце прокрутки
высота «Комментария» составляет 51 и 55 px соответственно.
В установленных сборках до и после совпали все записанные прямоугольники
и параметры прокрутки 16 состояний трёх форм Stalingrad.

## Установленный VSIX

VS Code 1.109.0, коммит Explorer `1c37fac`, SHA-256 локальной сборки
`92aa11a5e6828369681d6910efef568556085d1894ff46ae81b48ff0b3acfceb`.
Во всех 34 сравнениях ru/en совпали размеры рамки. Высота поля
совпала в 32 состояниях, одновременно высота и Y в 30, полный
прямоугольник в 10. Отдельная проверка на реальных формах сохраняла
исходные байты XML.

Полный прогон Node с реальным backend дал 768 pass, 9 skip, 0 fail.
Параллельная проверка Bun дала 15 сбоев в сценариях с API `node:test`
и необязательными инструментами. Проверка типов, сборка и упаковка
завершились успешно. Семь установленных сценариев прошли в ru/en,
всего 828 проверок. Они охватывают ширины колонок, размеры полей,
таблицы и их прокрутку, группы, галерею рендерера и формы Stalingrad.

## Воспроизведение

Контрольный сценарий в отдельном окне берёт `FooterWrapped.xml`,
добавляет `Height=16`, включает `VerticalStretch` у группы `Footer`
и оставляет автоматическую подпись `Amount`. После измерения поля он
меняет `MaxHeight` на 2, 3 и 5, переключает `VerticalAlign`,
убирает ограничение и восстанавливает исходный XML. Сценарий проверяет
сохранение выделения и DOM контролов. В Windows те же входы требуют
замеров с нативными метриками ОС.
[Входы и ожидания](../../tests/fixtures/forms/native-column-widths/README.md).
