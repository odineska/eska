# Фиксированная высота подвала и рамки Stalingrad в Linux

Конфигуратор 8.3.27.2342, «Такси», Linux ARM64, 96 DPI, масштаб 100%,
совместимость 8.3.27. Размеры контролов отсчитываются от верхнего левого
угла рамки. Контур поля измеряется по границе `#a0a0a0`, область итогов
по её фону. Размер области сравнения включает края выделенной рамки,
как в эталонах `FooterWrapped`.

## Многострочное поле в подвале

При `Bottom` соседняя группа итогов может выступать ниже предпочтительной
границы многострочного поля. При выключенном растяжении поля или его
группы с автоматической высотой место для итогов резервируется внизу
группы. То же правило действует, когда `MaxHeight` ограничивает поле
предпочтительной высотой. Поле сохраняет свою высоту. Размер резерва
участвует в измерении минимума группы. При фиксированной группе рендерер
задаёт рассчитанную высоту поля явно, чтобы вложенный CSS Grid получил
определённую высоту для строки с контролом.

| Состояние | Y / высота поля до, px | Y / высота поля после, px | Y / высота группы итогов после, px |
| --- | --- | --- | --- |
| `TallFixedDetails`, `Height=16`, у `Details` выключено растяжение | 255 / 40 | 239 / 51 | 255 / 40 |
| `TallTwo`, `Height=16`, `MaxHeight=2` | 244 / 51 | 239 / 51 | 255 / 40 |
| `FixedMemo`, растяжение поля выключено | 58 / 51 | 58 / 51 | 74 / 40 |
| `FixedDetails`, растяжение группы выключено | 58 / 51 | 58 / 51 | 74 / 40 |
| `Maximum2`, автоматическая высота формы | 58 / 51 | 58 / 51 | 74 / 40 |

В этих состояниях высота и Y поля и группы итогов совпали с Конфигуратором.
Совпал полный прямоугольник значения `Amount`. В группе `Details` значения
соседних подписей остаются на 1 px ниже. У `TallForm` с заданной высотой
формы и фиксированным подвалом растягиваемое поле занимает 51 px при
нативных 56 px. Четыре эталона проверяются через несохранённые правки XML
в отдельном окне с сохранением выделения и DOM элементов.
[Эталоны FooterWrapped](../../tests/fixtures/forms/native-column-widths/footer-wrapped-metrics.json).

## Повторные замеры Stalingrad

В изолированной копии «Менеджера займов» снято 12 кадров исходного
«Поступления на счёт текущих расчётов» на десяти профилях экрана. На прежнем
кадре с профилем 1400×1050 нижний край был обрезан областью редактора.
Полная рамка при том же профиле составляет 1084×737 px по принятому
способу измерения. XML формы до и после съёмки побайтно совпал с исходной
выгрузкой Stalingrad. Его SHA-256
`045dead34a69d01c6d83a354a9c2fb4f610302cd79a3a011636a2c1fce1821ef`.

Ниже прямоугольники Конфигуратора в порядке X / Y / ширина / высота,
в пикселях. Профили 1920×1080 и текущий монитор 2560×1760 дали одинаковые
размеры. При 1280×768, 1280×800 и 1280×1024 прямоугольники совпали.

| Профиль | Рамка | «Описание» | «Комментарий» | Группа итогов |
| --- | --- | --- | --- | --- |
| 1920×1080 | 1431×728 | 151 / 484 / 411 / 51 | 13 / 659 / 511 / 55 | 1127 / 687 / 283 / 27 |
| 1680×1050 | 1286×730 | 151 / 484 / 363 / 51 | 13 / 659 / 472 / 57 | 1026 / 676 / 239 / 40 |
| 1600×1200 | 1234×730 | 151 / 484 / 333 / 51 | 13 / 659 / 427 / 57 | 973 / 676 / 240 / 40 |
| 1400×1050 | 1084×737 | 151 / 484 / 257 / 58 | 13 / 666 / 313 / 57 | 823 / 683 / 240 / 40 |
| 1280×1024 | 994×759 | 151 / 484 / 211 / 80 | 13 / 688 / 257 / 57 | 733 / 705 / 240 / 40 |
| 1280×720, низ прокрутки | 994×718 | 151 / 443 / 211 / 80 | 13 / 647 / 257 / 57 | 733 / 664 / 240 / 40 |
| 1024×768, низ прокрутки | 646×761 | 81 / 472 / 114 / 51 | 13 / 692 / 127 / 55 | 465 / 701 / 160 / 46 |

При равной рамке 1084×737 px в Explorer «Описание» занимает 61 px,
а «Комментарий» имеет прямоугольник 13 / 669 / 320 / 56 px. Группа
итогов занимает 826 / 685 / 237 / 40 px. При 994×718 px Конфигуратор
сохраняет высоту «Описания» 80 px и прокручивает тело на 41 px. В Explorer
высота поля составляет 57 px, ход прокрутки 15 px. Это остающиеся
расхождения для расчёта высоты тела при сужении и ограничении окна.

Новый VSIX воспроизвёл эти замеры Explorer без изменений в 10 состояниях
исходной формы. Измерения в верхнем и нижнем положении прокрутки
сделаны в одинаковых рамках. В проверенном исходном XML `MaxHeight=4`
позволяет полю «Комментарий» расти выше предпочтительной высоты.

В отдельной тестовой конфигурации созданы копии исходной формы с
`Width=96`. На мониторе 2560×1760 исходная копия получила ту же высоту
759 px, что и форма при ограничении ширины профилем 1280×1024. Изменения
в остальных копиях проверены при той же ширине 994 px.

| Изменение в копии | Высота рамки, px | Высота «Описания», px | Y «Комментария», px |
| --- | --- | --- | --- |
| Только `Width=96` | 759 | 80 | 688 |
| `Описание.VerticalStretch=false` | 759 | 51 | 688 |
| `ГруппаОсновное.VerticalStretch=false` | 745 | 66 | 674 |
| `Описание.AutoMaxHeight=true` | 759 | 80 | 688 |
| Подпись «Дата идентификации» заменена на «Дата» | 752 | 73 | 681 |

Высота рамки зависит от переноса подписей справа и растяжения основной
группы. При выключении растяжения самого «Описания» рамка сохраняет
высоту, меняется заполнение выделенного места полем.

### Исходная высота при разных ширинах

В 19 копиях формы ширина задана в XML. На Linux с Explorer `79d2e10`
сняты исходная высота рамки и размеры группы «Даты параметров учёта».
При 984 и 994 px подпись «Дата идентификации» в Конфигураторе
занимает две строки, в Explorer одну. На ширинах 1004 и 1014 px высота
группы уже совпадает, а разница высоты рамки сохраняется.

| Ширина рамки | Высота рамки 1С / Explorer | Высота группы дат 1С / Explorer |
| ---: | ---: | ---: |
| 854 px | 772 / 755 px | 138 / 138 px |
| 974 px | 759 / 740 px | 138 / 138 px |
| 994 px | 759 / 733 px | 138 / 131 px |
| 1014 px | 759 / 733 px | 131 / 131 px |
| 1054 px | 744 / 727 px | 123 / 123 px |
| 1094 px | 730 / 727 px | 123 / 123 px |

На ширине 994 px выключение растяжения «ГруппаОсновное» уменьшает рамку
1С на 14 px до 745 px. Explorer сохраняет 733 px. Выключение растяжения
одной из двух дочерних групп оставляет нативные 759 px. При удалении
подвала разница сохраняется в рамке 674 / 650 px. При удалении
«Служебных» она уменьшается до 730 / 727 px. Эти замеры позволяют
отдельно проверять исходную высоту группы и последующее сжатие тела.

### Режим вертикальной прокрутки

На тестовых копиях с `Width=96` полная высота рамки составляет 759 px
во всех четырёх режимах `VerticalScroll`. При высоте окна 718 px
Конфигуратор сохраняет «Описание» высотой 80 px в Auto, `use` и
`useWithoutStretch`. В `useIfNecessary` поле занимает 66 px.
«Даты параметров учёта» сохраняют одинаковую геометрию. Кадры сняты
на русском интерфейсе. Расхождение исходной высоты тела в Explorer
при 994 px остаётся открытым.

Отдельный корпус фиксирует выбор сжатия или прокрутки для таблиц
в тех же режимах. На формах с явно заданной шириной исходная высота
динамического списка измеряется до ограничения по высоте окна.
[Эталоны области таблицы](../../tests/fixtures/forms/native-table-viewport/README.md).

### Отступы надписи в блоке дат

В серии из 19 замеров Stalingrad при совпадающем переносе подписи первой даты
первое поле под жёлтым блоком начиналось на 2 px выше эталона.
На контрольных формах с полем после блока эти 2 px приходятся на строку
надписи с типом «Дата» и боковой подписью. При подписи сверху разница
составляла 1 px. Замер повторён с однострочной и многострочной боковой
подписью, включая группу без заливки. Отступы теперь участвуют в замере
высоты строки и размещении поля.

В установленном VSIX у исходной формы в рамке 994×718 px высота
«Описания» выросла с 57 до 59 px, ход прокрутки с 15 до 17 px.
Исходная высота копии с `Width=96` выросла с 733 до 735 px.
В Конфигураторе остаются 80, 41 и 759 px соответственно. Первое поле
«Судебных данных» теперь начинается на Y=276 при нативном Y=283.
Разницу в 7 px в этом месте даёт пропущенная строка подписи
«Дата идентификации». [Эталоны блока дат](../../tests/fixtures/forms/native-united-layout/README.md#высота-блока-дат-с-надписью).

## Распределение ширины в подвале

Для 15 ширин и девяти дополнительных кеглей созданы формы с
компоновкой подвала Stalingrad и окрашенными значениями полей `Fixed`,
`Owner` и `Amount`. Геометрия 24 форм совпала на русском и английском
стенде Конфигуратора. В первом установленном VSIX измерены те же 24 рамки.
Иерархия соответствует `FooterWrapped`. Для групп использованы стандартные
оформление и поведение. У `Memo` включено `ExtendedEditMultipleValues`,
у `Fixed` включена гиперссылка, у `Memo` и `Amount` использовано
автоматическое положение подписи. В вариантах кегля одновременно менялись
шрифты подписи и значения `Amount`.
В `Width120` при рамке 1234×127 px нативное значение `Fixed` занимает
158 px при предпочтительных 152 px, а `Owner` ещё сжато до 136 px.
Explorer выделял им 152 и 137 px, а `Memo` получалось на 12 px шире
эталона. В `Width135` сумма уже имеет однострочную подпись, `Fixed`
остаётся двухстрочным. Высота `Memo` в Конфигураторе составляет 51 px,
в Explorer 55 px. В контрольных формах на 1094 px колонка двухстрочной
подписи `Amount` шире текущей на 3 px при 10 pt, на 2 px при 8 pt и
на 4 px при 14 pt. Ширины самих значений в этих замерах совпали. При
одиночном открытии `Width135` в Explorer `36d302c` и `8221d9d`
прежняя полоса прокрутки отнимала 15 px у рамки. Смена высоты строки
подписей теперь запускает повторное измерение минимума, в том числе
для вложенной группы итогов. При обновлении модели и изменении размера
для проверки переноса используется полная доступная ширина. В отдельном
окне проверяется переход из рамки 1364×127 px в 1374×122 px и 1384×122 px
через несохранённый XML. Высота `Memo` меняется с 56 до 51 px, `Summary`
с 40 до 29 px. В двух широких состояниях внутренняя прокрутка отключена.
В установленном VSIX прошли 494 случая `column-widths` и 62 случая
`responsive` в ru/en. Для ручного предела многострочного поля внутри
группы с заданной высотой тест использует метрику Linux 107 px.
[Матрица прямоугольников](t157-inline-footer-width-linux.json).

### Ширина ряда при переносе нескольких подписей

К исходным 24 состояниям добавлены 20 замеров порога переноса и пределов
ширины на ru/en, а также 26 замеров состава подписей на en. При явно
заданной ширине ссылочного значения от 6 до 30 единиц Конфигуратор
добавлял около 4% к предпочтительной ширине при переносе нескольких
подписей. При `HorizontalStretch=false` значение `Fixed` сохраняло 152 px.
В реализации запас ширины учитывается в сжатом боковом ряду и ограничен
исходным максимумом значения. При одной перенесённой подписи применяется
общий расчёт ширин.

В `Transition130` совпали ширина значения `Fixed` 158 px, прямоугольники
`Amount` и `Summary` и высота `Memo`. Ширина `Memo` составляет 507 px при
505 px в Конфигураторе, значения `Fixed` и `Owner` сдвинуты вправо на 1 px.
В `Width120` ширина `Memo` изменилась с 435 до 425 px при эталонных 423 px.
У экстремальных кеглей и некоторых длинных подписей остаются различия.

| Рамка Stalingrad | Ширина «Комментария» до / после / 1С, px | X и ширина группы итогов после / 1С, px |
| --- | --- | --- |
| 994×759 | 263 / 259 / 257 | 733 / 240, 733 / 240 |
| 1084×737 | 320 / 316 / 313 | 823 / 240, 823 / 240 |
| 1234×730 | 440 / 430 / 427 | 973 / 240, 973 / 240 |
| 1286×730 | 483 / 473 / 472 | 1025 / 240, 1026 / 239 |

При рамке 994×718 px подвал стал ближе по ширине, высота «Описания»
и ход прокрутки остались прежними. При 994 px высота жёлтой группы
«Даты параметров учёта» составляет 131 px при 138 px в Конфигураторе.
До прокрутки правый блок Конфигуратора имеет одинаковые координаты в
рамках 994×759 и 994×718 px. В варианте с короткой подписью «Дата» высота
окрашенной группы и полная высота рамки уменьшаются на 7 px.

## Установленный VSIX

В VS Code 1.109.0 с Explorer `8221d9d` размеры рамки совпали во всех
132 повторных замерах высоты.
Y и высота `Memo` совпали в 118 случаях, полный прямоугольник в 26.
Y и высота окрашенной группы итогов совпали в 82 из 106 случаев.
Проверка типов, сборка и упаковка прошли. В 12 UI-прогонах
установленного VSIX на русском и английском прошли 640 контрольных
случаев. В Node.js прошли 768 тестов, 9 сценариев пропущены для Windows
и необязательных инструментов. SHA-256 VSIX
`a19adb7b9f3f09818e02954d4eec93617212fb980afbf7eba0a270da2d04aec1`.

После поправок пересчёта высоты и распределения ширины проверка типов,
сборка и упаковка прошли. В 14 установленных прогонах ru/en прошли 710
случаев. Повторные замеры итогового VSIX совпали с пробной сборкой во всех
десяти размерах и положениях прокрутки Stalingrad. SHA-256 исходного XML
сохранился. В Node.js прошли 769 тестов, 9 пропущено. SHA-256 итогового
VSIX `5ad74f90c4d384160619df5557c39fd2bba159c73238e2932b72568b2501c17d`.

Сценарий сверки на второй ОС записан в руководстве приёмки.
