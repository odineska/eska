# Приёмка просмотра форм на Windows

По уточнению пользователя от 2026-11-02 текущая реализация T152–T165
принимается на Linux. Windows-приёмка выполняется следующим агентом на
отдельном стенде. Этот файл сохраняет её обязательный объём; Windows-проверки
пока не выполнялись.

## Эталон и входы

- Сравнивать с предпросмотром Конфигуратора 8.3.27 «Такси» на самой Windows.
  Linux-снимки не являются эталонами Windows.
- Зафиксировать полный build, ОС, DPI, масштаб формы, область, шрифты и язык.
  Linux-каталог проверяется на 8.3.27.2342; прежние отчёты Windows также
  использовали 8.3.27.2342, но актуальный стенд нужно проверить заново.
- Использовать [каталог](../../tests/fixtures/forms/catalog.json) и собственные
  минимальные формы, добавляемые в ходе T152. Сложные поля сверять именно
  с изображением Конфигуратора без выполнения BSL.
- Разворачивать все временные проекты в уникальных каталогах соседнего
  `eska-playground`; не изменять имеющиеся demo пользователя.

## Обязательные проверки

1. Полный каталог элементов, свойств, базовых стилей и переопределений;
   группы, страницы, таблицы и специальные поля.
2. Применение базы и расширений, ресурсы, шрифты и локализованные заголовки.
3. Установленный VSIX ru/en; независимость картинки формы от темы VS Code.
4. Dirty XML, Undo/Redo, внешние изменения, ошибочный XML и возврат актуальности.
5. Открепление/возврат окна, закрытие в обоих порядках, reload, несколько форм,
   мониторы с разным DPI и сохранение фокуса при обновлении.
6. Геометрия и снимки по процедуре T152; производительность по T164.

Сохранить фактические команды, версии, снимки и результаты по каждому сценарию.
Возможность запустить программу и совпадение каталога не подтверждают визуальную
приёмку. По мере реализации Linux здесь добавляются точные имена fixtures,
команды и ссылки на окончательные результаты.

## Реализация и актуальные Linux-сценарии

- Backend API 1.38; Explorer commit `14dce89` содержит первый SolidJS viewer.
  Последующие изменения продолжают калибровку; использовать HEAD обоих репозиториев.
- `test/form-preview-host.cjs` устанавливает VSIX и проверяет dirty XML, Undo/Redo,
  native floating window, общий выбор, внешний файл, переход в XML, последнее
  корректное изображение, восстановление ошибочного первого снимка, две формы,
  закрытие основной вкладки перед возвратом preview и освобождение сессий.
  Linux ru/en прошли эти сценарии. Обязательна независимая проверка Windows.
- `test/form-renderer-host.cjs` читает собственные fixtures из абсолютного
  `ESKA_FORM_FIXTURES`, который должен указывать на
  `<eska>/tests/fixtures/forms/native-bound-fields`. В галерее 20 форм;
  проверяются размеры контролов, высоты простых форм и образцы специальных полей;
  это ещё не полная пиксельная приёмка. Изначальные `native-fields` без DataPath
  нужны для каталога: Конфигуратор не рисует такие непривязанные поля.
- Для штатного Windows Undo/Redo нужен OS focus окна IDE. Linux-обход
  `ESKA_HOST_FOCUS_HELPER` — только для XWayland; не применять его на Windows.
- По решению пользователя случайные демонстрационные значения диаграмм
  исключаются из пиксельного сравнения. Геометрия, оси, подписи, легенда,
  палитра и оформление сравниваются полностью. Native-диаграмма меняет значения
  при каждом открытии без изменения XML или исполнения BSL.
- Локаль IDE и региональное представление календаря различаются: на Linux
  1C UI был ru, но LANG=C.UTF-8 давал en-US названия месяцев и начало недели
  с воскресенья. В отчёте Windows фиксировать оба параметра.
- Linux-метрики по умолчанию и оставшиеся расхождения ширины подписей находятся
  в [t158-bound-fields-linux.json](t158-bound-fields-linux.json). Их нельзя
  автоматически считать Windows-эталоном. Там же отмечены native-образцы
  переключателя, индикатора, ползунка и планировщика. Английские образцы сверены
  с `/L en`, русские — с `/L ru`.
- Для `RadioButtonField` повторить [матрицу переключателей Linux](t158-radio-choices-linux.json)
  в родном профиле Windows. Сверить порядок вариантов при неполном столбце,
  расположение и общие границы сегментов `Tumbler`, увеличенный шрифт,
  цвет текста, недоступное состояние и влияние хвостовых пробелов. Сценарий
  `renderer` меняет тип из несохранённого XML в отдельном окне и возвращает
  результат во вкладку. Linux-отчёт хранит отличия растра и один открытый
  пиксель ширины рамки.
- `test/form-pictures-host.cjs` проверяет общую картинку, внешнюю замену SVG
  и переключение файла через dirty `Picture.xml`; `test/form-application-host.cjs`
  читает выбранные формы существующего приложения без записи и сохраняет
  замеры первого изображения. Оба сценария запускаются с актуальным VSIX.
- В `native-field-overrides` есть включение/выключение `AutoMarkIncomplete`.
  Linux-проверка отметки и наследования привязок описана в
  [t155-form-bindings.json](t155-form-bindings.json). Windows должен подтвердить
  своё изображение этого состояния; dirty XML уже включён в общий host-сценарий.
- `test/form-tables-host.cjs` использует `ESKA_FORM_FIXTURES`, указывающий на
  `<eska>/tests/fixtures/forms/native-tables`. Девять форм покрывают пустые
  таблицы, три способа группировки шапки, подвал, чтение, отметку заполнения
  и отключение автозаполнения. Linux-метрики сохранены в
  [t159-native-tables-linux.json](t159-native-tables-linux.json); ширины и
  шрифты на Windows нужно измерить независимо. Проверить также ограничение
  ширины поиска в широкой таблице и автоматическую подпись номера строки `N`.
- В `native-bound-fields` теперь все 20 привязанных видов. Семь новых
  native-эталонов, контекстные таблицы и варианты дополнений описаны в
  [t160-native-complex-linux.json](t160-native-complex-linux.json).
  Принимать их рендерер отдельно: наличие XML и успешный import не означают
  завершения Solid. Поле периода показывает три года, а не два поля даты.
  Проверить региональную локаль названий месяцев и текущую дату стенда.
- Для расширенной табличной галереи передать дополнительно абсолютные
  `ESKA_FORM_CONTEXT_FIXTURES=<eska>/tests/fixtures/forms/native-context-tables`
  и `ESKA_FORM_ADDITION_FIXTURES=<eska>/tests/fixtures/forms/native-addition-variants`.
  Тогда `form-tables-host.cjs` проверяет 13 случаев. Native-дендрограмма
  и Гант на Linux не меняли образцы при повторном открытии; их содержимое
  не исключено из сравнения как случайное.
- Галерея 20 полей проверяет dirty `Visible` дополнения PDF, размеры периода,
  схему и текстовое поле. Английский native-Гант показывает четвёртую точку
  с дополнительными синим/оранжевым интервалами: подпись `Value` занимает меньше
  строк, чем `Значение`. Это содержимое не случайное. Измерить свои шрифты,
  переносы, полосы прокрутки и цвета Windows; Linux-доли RGB-совпадения
  приведены в отчёте T160 и не означают полной приёмки.
- `test/form-states-host.cjs` использует `ESKA_FORM_FIXTURES`, указывающий на
  `<eska>/tests/fixtures/forms/native-state-variants`; в галерее 15 состояний.
  Проверить видимость, пустую форму, disabled/read-only, цвета, размеры
  шрифта и региональные маски. [Linux-замеры](t157-native-field-states-linux.json)
  не заменяют измерение шрифтов и размеров Windows.
- Дополнительный `ESKA_FORM_STATE_FIXTURES=<eska>/tests/fixtures/forms/native-state-variants`
  включает в табличную галерею скрытую колонку: всего 14 случаев.
  Native-английские панели Linux шире русских из-за `More actions`;
  минимумы 429/454 px записаны в матрице состояний. Проверить свои
  английские подписи и размеры Windows.
- Галерея `test/form-groups-host.cjs` клиента и
  `ESKA_FORM_FIXTURES=<eska>/tests/fixtures/forms/native-groups` добавляет
  18 случаев групп/страниц/команд/стилей. Генератор также копирует два
  собственных `StyleItem`. [Linux-эталоны](t157-native-groups-linux.json)
  фиксируют `TitleFont`, цветные отступы, сильное разделение и раскрытое
  проектное состояние `Collapsed=true`. Для Windows сначала снять свои
  размеры и адаптировать ожидания тестов; Linux-геометрия не является
  критерием Windows. В частности, новое округление ширин команд/вкладок
  включено только в профиле Linux.
- При проверке взаимодействия использовать реальные клики webview: они
  должны доходить до extension host без `DataCloneError`. Unit-тест
  `form-controller.test.mjs` отдельно проверяет structured-clone границу.
- `test/form-activity-host.cjs` клиента создаёт собственный workspace
  base/extension и отдельный `ESKA_CONFIG_DIR`. Проверить dirty XML при
  отключении/включении расширения и владельца формы, включая отдельное
  окно. Документ должен остаться dirty, DOM — сохраниться, XML и manifest —
  не измениться. Фильтр списка проектов должен сохранять `formSessionId`.
  Этот сценарий проходит на Linux в ru/en и не требует установленной 1С.
- Дополнительный `ESKA_FORM_TABLE_COMMAND_FIXTURES=<eska>/tests/fixtures/forms/native-table-commands`
  расширяет табличную галерею с 14 до 16 случаев. Проверить `Popup` и
  `ButtonGroup` в панели таблицы, отсутствие «Ещё» при `Autofill=false`,
  скрытый поиск `SearchStringLocation=None`, выбор XML ID 220 и dirty-подпись
  в открытом меню без замены DOM. [Linux-измерения](t159-native-table-commands-linux.json)
  сохраняют строгие RGB-доли; полное совпадение и Windows-метрики не приняты.
- `test/form-dependencies-host.cjs` клиента создаёт собственную форму и три
  элемента шрифтового стиля без внешних fixtures. На Linux ru/en проходят
  смена новой dirty-зависимости, цепочка стилей, её удаление и возврат,
  ошибки XML и восстановление в отдельном окне. До стабилизации накладок
  промежуточная модель не публикуется; ошибка нового dirty-ресурса сохраняет
  последнее показанное изображение. Проверить тот же контракт Windows.
  [Linux-результаты](t162-dirty-dependencies-linux.json) также фиксируют
  открытый случай повреждённого дискового файла до первого обнаружения.
- В API 1.38 этот случай закрыт подготовкой входов: `form/prepare` возвращает
  активные корни и составляющие формы без разбора их XML; dirty-тексты передаются
  в `inputs` при открытии/обновлении. Актуальный `form-dependencies-host.cjs`
  дополнительно повреждает на диске первый новый стиль и вторую форму,
  сохраняя корректные dirty-буферы. Проверить обе формы без записи файлов,
  чужие формы/корни, traversal и нормализацию разделителей ID на Windows.
  Фокус основного workbench перед командой открытия второй формы обязателен:
  активное отдельное окно может не иметь `activeTextEditor`.
  [Проверки подготовки входов 1.38](t162-input-preparation-linux.json).
- `test/form-lifecycle-host.cjs` проверяет закрытие последней панели при
  удержанном успешном ответе `prepare`, `open` и `update`. Для обновления
  последним потребителем остаётся отдельное окно. После ответа все настоящие
  подписки наблюдения должны быть освобождены, а `form/get` выделенной сессии
  должен вернуть `unknown_form_session`. XML не меняется. Этот сценарий
  [проходит на Linux ru/en](t163-pending-close-linux.json); повторить на Windows.
- `test/form-reconnect-host.cjs` проверяет disconnect/connect и restart backend
  с удержанным ответом старого обновления. PID процесса должен измениться,
  прежний процесс — завершиться; короткий `formSessionId` может повторяться
  в другом процессе и сам по себе не доказывает замену. Dirty XML, выделение
  и DOM отдельного окна сохраняются; поздняя старая модель не публикуется.
- `ESKA_HOST_RESTART=1` и `test/form-restore-host.cjs` запускают установленный
  startup probe в обычном VS Code. Сначала выполняется настоящий reload окна,
  затем полное завершение и запуск с тем же профилем. Проверить hot exit dirty
  XML, две панели и native floating window, выделение/страницу, разные масштабы,
  высоту областей и последующие живые обновления. Для завершения probe использует
  `workbench.action.quit`: `closeWindow` закрывает активное отдельное окно.
  [Linux ru/en](t163-restart-linux.json) не заменяет Windows и DPI-приёмку.
- `test/form-inspectors-host.cjs` создаёт собственный XML со строковым заголовком
  `true`, логическими свойствами, атрибутами шрифта, повторяющимися событиями и
  чужим `Width`. Проверить подписи ru/en, флажки только для известных типов,
  раскрытие записей, сохранение их DOM при dirty-обновлении и F12 к точному XML.
  Диапазоны должны учитывать BOM и нормализацию смешанных LF/CRLF редактором;
  реальные отличия текста по-прежнему запрещают навигацию. Служебные ключи Solid
  не заменяют XML QName. [Linux-проверки](t161-form-inspectors-linux.json)
  не подтверждают полный словарь и переходы к BSL-обработчикам.
- Галерея `test/form-groups-host.cjs` теперь содержит 22 случая и все семь
  значений `FormPagesRepresentation`. Native XML использует
  `TabsOnLeftHorizontal`/`TabsOnRightHorizontal`; `Auto` может отсутствовать
  в экспорте. Для эталона нужен предпросмотр Конфигуратора: на Linux `Swipe`
  рисуется как верхние вкладки. Проверить размеры при переключении, отсутствие
  переноса подписей, выбор страницы через дерево в отдельном окне и dirty
  `Visible` выбранной страницы. Невидимые панели участвуют в выделении размера,
  но скрыты и недоступны для взаимодействия. В тестах нужно выбирать видимую
  панель, а не первый совпавший скрытый узел. [Linux-измерения](t157-native-pages-linux.json)
  включают всю форму и тень без масок; полное пиксельное совпадение не принято.
- Общая рамка и выделение теперь имеют отдельные Linux-правила. На Windows
  заново измерить толщину внешней рамки, фон/шрифт заголовка, тень и положение
  выделения корня, вкладки и поля. Слой выделения не должен менять компоновку.
  [Linux-отчёт](t156-native-frame-selection-linux.json) фиксирует точное
  совпадение координат выделения трёх собственных состояний, но сохраняет
  различия всей формы и не подтверждает остальные виды элементов или Windows.
- API 1.39 добавляет `formPreview.handlerNavigation` и переходы из событий/
  действий команд. Запустить `test/form-handlers-host.cjs` в ru/en: dirty XML и
  BSL, кириллица/BOM/CRLF, повторные события, command Action, поздний ответ,
  upload модуля и закрытие последнего окна во время передачи. Модуль выбирается
  по происхождению XML-свойства, существующие source URI/ограничения поддержки
  сохраняются. Проверить их на Windows отдельно. Отсутствующее/неоднозначное
  объявление не должно делать модель формы устаревшей или создавать BSL.
  [Linux-проверки](t161-form-handlers-linux.json) не закрывают матрицу BSL-цепочек
  расширений и native-сверку всех видов обработчиков.
- На Linux боковые подписи полей округляют ширину по содержимому до ближайшего
  целого CSS-пикселя; сам кегль сохраняется. Не переносить округление шрифта
  на Windows: [Linux-эксперимент](t157-native-label-allocation-linux.json)
  показал ухудшение при таком изменении. Новые строгие координаты в галерее
  относятся к Linux `Auto`/`Swipe`; Windows нужно измерить отдельно.
- Для `InputField` общий backend теперь выбирает `FieldTextColor` для значения
  и `FormTextColor` для подписи. Проверить выбранный стиль с разными цветами
  этих ролей и явные XML-переопределения. Linux-палитра уточнена по двум
  native-эталонам `native-palette`; Windows-цвета не переносились из Linux.
  `test/form-palette-host.cjs` проверяет только цветовые роли. Размеры 32 pt
  остаются незакрытой частью приёмки; [отчёт](t155-native-color-roles-linux.json)
  явно сохраняет расхождения геометрии.
- Добавлена галерея `native-button-metrics`: 16 собственных форм с 48 кнопками
  обычного/полужирного шрифта 10–32 pt. Их геометрия теперь совпадает на Linux;
  [отчёт](t156-native-button-metrics-linux.json) сохраняет пиксельные расхождения.
  На Windows заново снять native-размеры, отступы, строку и ширину подписей.
  `test/form-button-metrics-host.cjs` содержит Linux-ожидания под проверкой ОС;
  его `passed` на Windows не означает проверки геометрии. Нужны собственные
  Windows-ожидания и обязательные assertions. Таблица FreeType 2.13.2 и новые
  отступы применяются только в Linux-профиле; не включать их на Windows без
  измерений. Проверить dirty-переход 16 → 20 → 16 pt и отсутствие записи XML.
- В Linux обычная доступная кнопка с текстом использует дискретную заливку
  фона без dithering Chromium. [Проверка](t156-native-button-backgrounds-linux.json)
  охватывает строки фона 48 кнопок, а не весь набор свойств и состояний.
  На Windows эта заливка не включена. Отдельно измерить native-градиент,
  углы и границы. Проверить переключение `DefaultButton` из dirty XML:
  обычная заливка должна уступать оформлению основной кнопки и возвращаться
  при снятии свойства; XML не сохраняется.
- Обычные подписи кнопок Linux теперь используют комплектный FreeType WASM,
  не установленную 1С или системную библиотеку. Профиль Windows его не включает.
  [Linux-проверка](t156-native-button-captions-linux.json) подтверждает только

Этот воспроизведённый сценарий отличается от единичного наблюдения target-title
в проверке дат; последнее остаётся открытым.

Продолжение T163: [два независимых окна Linux](t163-multiple-preview-windows-linux.json).

одного исходника, больше двух окон, мониторы/рабочие столы и DPI требуют
дальнейшей приёмки. Причина прежнего единичного target-title не установлена;
с новой адресацией в этих десяти запусках наблюдение не повторилось.

Основная кнопка Linux: [корпус и результаты](t158-native-primary-buttons-linux.json),

Windows-приёмку. 51 форма принимает прямоугольные области внутри кнопок с
отступом 3 px. Рамки, углы, тени, автоматические команды корневой панели,
height="0", другие состояния/шрифты и DPI ещё открыты. Шрифтовые случаи
использованы для уточнения правил; независимыми названы только 4096 новых

пока точный frame покинет главную page. Это не объясняет автоматически прежнее

перемещение области меняло несколько пикселей рамки и иногда нижнюю границу
RGB 155/156 при одинаковом XML. При полной сверке сохранять положение области
и DPI, сравнивать все пиксели. Причина в библиотеке не установлена. Вход

Полные кнопки Linux: [измерения](t158-native-button-borders-linux.json),

native-primary-buttons). Проверены все пиксели 153 поднятых текстовых кнопок,

новая приёмка не отменяет native-button-poses и не разрешает новые маски.

вход для `test/form-responsive-host.cjs` Explorer, а не пиксельный эталон Windows.
Проверять его вместе с четырьмя read-only формами из пользовательской demo.
Размер области определяется контейнером в CSS px; zoom задаётся отдельно.
Измерение предпочитаемой геометрии отделено от выделения текущего места.

В Linux-драйвере есть CSS-циклы 360×240 → 640×360 → 1000×680 → 640×360 →
исходная область и изменения настоящих окон 900×600 → 1440×900 → 1100×700 →
исходное окно. Повторить в основной вкладке и откреплённом окне, с разделителями,
zoom 125%, dirty XML и штатными Undo/Redo. Проверять сохранение DOM, выделения,
страницы, свёрнутой группы и независимость размеров двух окон. Resize не должен
отправлять `form/*` RPC, менять исходники или создавать сессию.

`test/resize-native-workbench.py` сейчас использует X11 и проверяет PID, класс,
заголовок и геометрию собственного изолированного VS Code. Для Windows нужен
свой способ изменения размеров только окна тестового процесса; Linux-помощник
там не работает. Не подменять изменение настоящего окна одним CSS-тестом и
не изменять окна пользовательского рабочего профиля.

Проверять фиксированную группу и поля, веса растяжения, рассчитанные минимумы,
MaxWidth/MaxHeight, HorizontalIfPossible, вложенные страницы, маленькую область
с прокруткой и широкие колонки таблицы с внутренней горизонтальной прокруткой.
Canvas должен сохранять DOM и получать новый буфер по выделенным размерам,
с перерисовкой текста и линий. Растяжение последнего bitmap не принимается.

Старые геометрические/пиксельные драйверы вызывают
`frame({fixedFormArea:true, ...})`: тест закрепляет область по предпочитаемой
геометрии, чтобы сохранить прежние native-эталоны после изменения поведения
продукта. Это не выключает адаптацию в установленном расширении. Критерии
пиксельного сравнения остаются прежними; на Windows требуются собственные
метрики, шрифты, DPI и снимки Конфигуратора соответствующей ОС. Полная native-
матрица размеров и ограничений, в том числе начальная высота самой формы,
этой функциональной Linux-проверкой не закрывается.

Перенос в отдельное окно должен ждать фактической активации вкладки изображения
в модели TabGroups, а затем повторно проверять её после фокусировки редактора.
У новой WebviewPanel значение `active` может появиться до завершения открытия:
в Linux это однажды привело к переносу основной панели. Исправление Explorer
`105a9e0` проверено повторными циклами, двумя окнами и reload/restore в ru/en.
На Windows проверить тот же сценарий и сохранение основной панели на месте.
Тестовый драйвер определяет владельца конкретного iframe по дереву native-окон;
одного совпадения заголовка или первого popup недостаточно. При сравнении пикселей
ожидать появление нужной рамки выделения; обнаруженное RGB-различие не повторять
до случайного успеха и не скрывать маской.


Для освобождения основной области при откреплении повторить
`test/form-detached-space-host.cjs`: заглушки и горизонтального разделителя
нет, инспекторы занимают shell минус toolbar/status, раскрытые свойства и DOM
сохраняются. Проверить маленькое окно, штатное закрытие floating-окна,
повторное открепление и возврат. В `form-restore-host.cjs` сохранённые 240 px
проверяются после возврата изображения; во время открепления ожидается полная
полезная высота. Обновление геометрии не должно перезаписывать эти 240 px.


Матрица локализаций в `test/form-inspectors-host.cjs` проверяет единственный
перевод, другой язык, несколько переводов, пустое содержимое, отсутствие
вариантов, внешние/внутренние аннотации и неизвестное вложенное поле. Повторить
в ru/en; одиночный вариант должен быть обычным текстом, остальные данные
остаются доступны. Проверить dirty-переход 1 → 2 → 1 и раскрытие соседней
записи событий. Эта проверка не подтверждает полноту каталога свойств/default.
