# Повторная приёмка Windows: библиотеки и workspace

Проверены изменения после `43cfadf4950d1916b2f87d221c465a85b6a502c3`
в выбранной ветке `codex/design-xml-analyzer`. Связанный Explorer принят
из `b44736d3b25d9bcd7f2f798c84784bb5d7bbd67e` в отдельной рабочей копии.
Машинные результаты: [измерения](measurements/windows-review-2026-10-31.json).

Среда: Windows 11 x64, build 26100, i5-6200U, 8 GiB RAM,
Rust 1.99.1 / MSVC 14.44, 1С 8.3.27.2342, Microsoft VS Code 1.144.0.
Проверяется Designer XML; новые форматы и следующие этапы roadmap не добавлены.

## Исправления ревью

- Каталог библиотек публикуется через стандартный `fs::rename` на всех ОС.
  Прежняя Windows-последовательность с резервным переименованием оставляла
  промежуток, когда `config.toml` отсутствовал. Регрессия с параллельным чтением
  воспроизводит старый сбой и проходит после исправления.
- `DirBuilder` активности и очистка Windows read-only атрибута проходят строгий
  Clippy. Unix-права и Windows-атрибуты обрабатываются в своих platform branches.
- Нативные сценарии поддерживают Windows host, `.exe`, обычные пути для `ibcmd`
  и UTF-8. Ctrl+Break отправляется только в собственную скрытую консоль.
  Тайм-аут завершает собственное дерево процессов и сохраняет журналы.
- Очистка временных тестовых каталогов ожидает освобождения Windows-дескрипторов
  не более пяти секунд. При уже возникшей panic ошибка очистки печатается,
  сохраняя первоначальный сбой вместо аварийного завершения всего test executable.

## Результаты

`cargo fmt --check`, `cargo check --locked`,
`cargo clippy --all-targets --all-features --locked -- -D warnings` — PASS.
Полный `cargo test --locked --workspace --no-fail-fast -- --nocapture`:
**1293 passed, 18 ignored, 0 failed**. Оба профиля собирались без debug information;
`ESKA_TEST_ROOT` указывал на абсолютный путь соседнего `eska-playground`.
Python-проверки компонентов и установщика: **52 tests, 19 skipped, PASS**.

Настоящий `ibcmd` подтвердил CF/CFE/EPF/ERF: build, повтор с переиспользованием ИБ,
unpack, паспорт и clean. Отмена build/unpack сохраняет опубликованный результат,
удаляет staging и завершает дочерний процесс.

Отдельная XML-библиотека с `CatalogRef.Products` проверила автоматическую основу
EPF/ERF, отрицательный контроль без библиотеки, равенство native XML при явном CF,
общий CF без паспорта производителя, неизменяемый шаблон ИБ, два параллельных
потребителя, обновление исходников, отмену подготовки, workspace и selectors.

Настоящие БСП 3.1 и 3.2 установлены встроенным HTTPS-транспортом в штатный
пользовательский managed directory. Подтверждены точный `master` commit,
shallow history из одного commit, повтор без VCS/сети в ru/en и сохранность
исходников, manifest и машинной политики. БСП 3.1 также подготовлена в общий CF
размером **85 701 675 bytes**; первая подготовка на этом ПК заняла **926,8 s**.
Это измерение холодной подготовки, а не обещание такой же скорости на другом ПК.

## Повторение

Сырые журналы текущего запуска находятся в
`../eska-playground/windows-review-20261031-195814`.
Проекты создавались только в собственных уникальных соседних demo-каталогах.
Существующие пользовательские demo не изменялись.

`tests/native_build.py` принимает Windows host без `--distrobox`.
Для `tests/native_libraries.py` нужны `--library-source`, `--catalog`,
`--platform-version`, `--platform-arch` и `--ibcmd`; путь библиотеки копируется
в новый stand. Для большой БСП на медленном диске задайте
`--timeout-seconds 1800`: стандартный лимит сценария — 240 s на команду.

Результаты относятся к Windows x64 и установленной 1С 8.3.27.2342.
Они не расширяют матрицу поддерживаемых версий платформы или Native patch.
